# 3.9 Learning Parameterized Policies

In tabular RL we stored one value per state (or per state–action pair). That's fine for tic-tac-toe, but it collapses under the weight of anything realistic — a robot arm has infinitely many joint angles, an Atari frame has millions of pixels. **Parameterized policies** replace the giant lookup table with a small function whose behavior is controlled by a handful of numbers (the parameters). Tune the numbers, change the behavior.

This lecture is the bridge between "policy iteration on a table" and "policy gradient methods" like REINFORCE, which are covered next.

## What Is a Parameterized Policy?

A **parameterized policy** is a function

```
π(a | s, θ)
```

that, given a state `s`, returns a probability distribution over actions `a`, controlled by a parameter vector `θ` (theta — think of it as the "knobs" of the policy).

Analogy: instead of writing a phone book of every state, you write a *recipe* — "if the state looks like X, lean toward action Y" — and the recipe's dial positions are `θ`.

### Constraints — it must still be a valid policy

Any parameterization we choose has to produce a **proper probability distribution**:

- Each action probability must satisfy `π(a|s,θ) ≥ 0`.
- For every state, the probabilities must sum to one: `Σ_a π(a|s,θ) = 1`.

If these are violated, "policy" stops meaning what we think it means, and the math underneath (returns, advantages, gradients) breaks.

## Softmax Policy Parameterization

The most common discrete-action parameterization is the **softmax over action preferences**.

- Let `h(s, a, θ)` be a **preference** score for taking action `a` in state `s`. The bigger the preference, the more we like that action.
- Convert preferences into probabilities with the softmax:

```
π(a | s, θ) = exp(h(s, a, θ)) / Σ_{b ∈ A} exp(h(s, b, θ))
```

Exponentiate the preferences (so they're positive), then normalize so they sum to one. The softmax is the same formula used in multi-class classification — that's not a coincidence; picking an action *is* multi-class classification.

### Preferences ≠ Action values

Important warning: **action preferences `h` are NOT action values `Q(s,a)`**. They just *rank* actions; they aren't estimates of expected return. If you set `h = Q`, the resulting policy is already a softmax of value estimates — fine, but conceptually these are separate objects.

### Tiny example

In a 3-action grid world, suppose in state `s` we have preferences `h(s, left) = 1`, `h(s, up) = 2`, `h(s, right) = 0`. Then:

```
exp = [e^1, e^2, e^0] ≈ [2.72, 7.39, 1.00]
π(·|s,θ) ≈ [0.245, 0.665, 0.090]
```

`up` is most likely, `left` next, `right` unlikely — but not impossible. That's the soft, exploratory behavior we want during learning.

## Why Parameterize? The Big Advantages

1. **Compact representation.** A million-state environment becomes a vector `θ` of maybe a few hundred weights. The policy is no longer a million-entry table — it's a *few numbers*.
2. **Generalization.** Updating `θ` because state `s_47` did well automatically adjusts behavior in *similar* states `s_48, s_49`. Tabular methods can't do this; they treat every state as its own island.
3. **Continuous action spaces.** A table can't list every real-valued action, but a function of `a` (e.g., a Gaussian `π(a|s,θ) = N(μ(s,θ), σ²)`) handles them naturally.
4. **Flexibility.** Any function approximator works — linear features, decision trees, neural networks. Pick the tool that fits the problem.
5. **Complex / high-dimensional states.** Neural-network policies can ingest raw pixels, robot sensors, or board positions directly. This is what powers modern deep RL (AlphaGo, DQN, PPO).
6. **End-to-end learning.** Because the policy is differentiable, you can directly optimize it to maximize cumulative reward — no hand-crafted features or intermediate steps.

## How Learning Will Work: A Glimpse of Policy Gradients

Because `π(a|s,θ)` is differentiable in `θ`, we can do **gradient ascent on policy quality**. The classic update (REINFORCE, Williams 1992) is:

```
Δθ = α · G_t · ∇ ln π(A_t | S_t, θ)
```

where `G_t` is the actual return observed after time `t`. Intuition: **hill-climbing on policy quality** —

- If `G_t` was high and we took action `A_t`, **nudge `θ` to make that action more likely in `S_t`**.
- If `G_t` was low, **nudge `θ` away from that action**.
- `∇ ln π` is the *score function*: how much does a tiny change in `θ` change the log-probability of the action we took?

This is the equation to remember — the rest of the chapter is refinements (baselines, actor-critic, GAE) of this one idea.

## Real-Life Analogies

- **GPS vs. memorized route.** A tabular policy is "turn left at every intersection you memorized." A parameterized policy is "follow the GPS — same algorithm, every city, parameterized by your start and destination."
- **Recipe vs. shopping list.** A shopping list enumerates every ingredient (table). A recipe tells you the *ratios* (parameters) and you scale up or down. Tweak the salt parameter, the whole dish changes consistently.
- **Thermostat vs. hand-tuned heater.** The thermostat has one knob (`θ`) and generalizes across every room temperature; the hand-tuned heater has a separate setting for every room.

## Common Pitfalls

- **Forgetting the constraints.** If you parameterize with raw linear scores and forget the softmax, probabilities can go negative or sum to more than 1.
- **Confusing preferences with values.** They look similar but play different roles.
- **Optimism bias early on.** With no constraint on the magnitude of `h`, one bad trajectory can send `θ` flying. Baselines and trust regions (later lectures) fix this.

## Key Takeaways

- A **parameterized policy** `π(a|s,θ)` replaces a giant table with a function controlled by a parameter vector `θ`.
- The parameterization must always produce a valid probability distribution (non-negative, sums to 1).
- The **softmax policy** turns action preferences `h(s,a,θ)` into probabilities via `exp(h) / Σ exp(h)`.
- **Action preferences ≠ action values**: they rank actions but don't estimate expected return.
- Parameterization gives **compactness, generalization, continuous-action support, flexibility, and end-to-end learning** — the backbone of deep RL.
- Learning works by **gradient ascent on policy quality**: `Δθ = α · G_t · ∇ ln π(A_t|S_t,θ)` (REINFORCE). High return → make that action more likely; low return → push away.
- Modern RL (PPO, SAC, AlphaZero) is essentially "parameterized policy + fancy gradient update + good function approximator."
