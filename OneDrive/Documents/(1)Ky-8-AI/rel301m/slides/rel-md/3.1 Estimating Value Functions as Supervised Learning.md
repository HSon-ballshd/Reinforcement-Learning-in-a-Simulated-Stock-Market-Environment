## Why Move Beyond a Lookup Table?

In the tabular setting, every state stores its own value:

```
V(s)  ←  table[s]
```

You update each entry as learning progresses. This works for small, discrete environments — chess, tic-tac-toe, the toy grid worlds you've seen so far. The moment the state space gets large (Go, robotics, Atari pixels) or **continuous** (joint angles, velocities), a table is no longer feasible. We can't store a value for every point in a continuous space — there are infinitely many of them.

**Analogy:** Instead of memorising a phone book of every resident's height, learn a smooth function like `height ≈ age * 0.7 + 80` and *generalise* to ages you have never seen. Function approximation is exactly that idea applied to value functions.

---

## Parameterized Value Functions

Instead of storing values per state, we choose a family of functions and adjust their parameters:

```
V̂(s, w) ≈ v_π(s)
```

- `V̂(s, w)` — our **approximate value function**.
- `w` — a vector of real-valued **weights** that we adjust during learning.
- The function takes a state and outputs a single number (an estimate of how good that state is).

A concrete (non-learnable) example: in a 2-D grid, `V̂(s) = X + Y` is fixed. Once you write it, you cannot change it. To make it learnable, we expose the coefficients:

```
V̂(s, w) = w_1 * X + w_2 * Y
```

Now changing `w_1` and `w_2` changes the entire value surface — we don't need a separate entry per cell.

> **Joke:** A table is like a parrot — it memorises exactly what you teach. A parameterized function is like a maths student — it learns a formula and applies it everywhere.

## Linear Value Function Approximation

The simplest useful parameterisation is **linear**. Each state is described by a **feature vector** `x(s) ∈ ℝ^d`, and the value is the inner product with the weight vector:

```
V̂(s, w) = wᵀ x(s) = Σ_i w_i * x_i(s)
```

- `x_i(s)` are the **features** — fixed, hand-crafted attributes of the state (e.g. distance to goal, number of walls nearby, battery level).
- `w` are the **learned weights**.
- The output is a single scalar value estimate.

This is appealing because the math is friendly: gradients are just the features themselves, and the optimisation surface is convex (a single global minimum for least-squares).

### Limitations of Linear Approximation

| Limitation | Why it hurts |
|---|---|
| **Linearity assumption** | Real value surfaces are usually curved; a hyperplane can underfit badly. |
| **Limited expressiveness** | Cannot capture interactions between features unless you engineer them manually (e.g. `x_i * x_j`). |
| **Feature engineering dependency** | You, the human, must pick the right features. Bad features ⇒ bad values, no matter how much data you have. |
| **Curse of dimensionality** | In high-dimensional state spaces, even storing the feature vectors becomes expensive. |
| **Difficulty with nonlinearity** | Some value functions are inherently non-linear (think `max` over actions in Q-learning). |
| **Sensitivity to noise** | Irrelevant or noisy features get non-zero weights and degrade generalisation. |

This is why non-linear approximators (decision trees, neural networks, kernel methods) are widely used in practice — at the cost of losing the nice convex loss landscape.

## Generalisation vs Discrimination (in the ML sense)

The slides separate two words that often get confused.

### Generalisation

The **ability of a model to perform accurately on new, unseen data that is similar to what it was trained on**.

- Goal: predict well on held-out test data.
- Evaluated with metrics like **accuracy**, **precision**, **recall**, or **mean squared error**.
- A *desirable* property — it's the whole reason we approximate rather than memorise.

### Discrimination (negative sense)

The **act of making unjust distinctions between individuals or groups** based on characteristics like race or gender.

- Has no legitimate purpose in ML modelling.
- Evaluated by asking whether a model's outputs depend on irrelevant, protected attributes.
- **Should be avoided** — this is a fairness / ethics concern, not a modelling goal.

> **Exam tip:** If an exam question asks "what is generalisation in RL?", answer: *the ability of a value-function approximator to assign sensible values to states it has never visited because it has learned a smooth functional form*, not the ethical concept.

## Supervised Learning for Value Estimation

RL data is **not i.i.d.** — successive states come from a trajectory, are correlated, and the distribution shifts as the policy improves. Still, at any snapshot we have a dataset:

```
D = { (s_1, v_π(s_1)), (s_2, v_π(s_2)), ..., (s_N, v_π(s_N)) }
```

We can frame value-function estimation as a **supervised regression problem**: predict the true value `v_π(s)` from the state `s` using features `x(s)` and weights `w`. The standard mean-squared-error loss is:

```
J(w) = E_π [ ( V̂(s, w) − v_π(s) )² ]
```

Why this is natural:

- States play the role of **inputs**.
- True values `v_π(s)` (or sample returns `G_t`) play the role of **targets / labels**.
- The approximator plays the role of a **regression model**.

### Gradient Descent Update

Taking the gradient of `J(w)` with respect to `w` and stepping opposite to it:

```
Δw = − (1/2) * α * ∇_w J(w)
   =   α * E_π [ ( V̂(s, w) − v_π(s) ) * ∇_w V̂(s, w) ]
```

For linear approximation `V̂(s, w) = wᵀ x(s)`, the gradient is just the feature vector:

```
Δw = α * ( v_π(s) − V̂(s, w) ) * x(s)
```

This is the **Widrow–Hoff / LMS rule** — and it is the seed from which RL methods like TD(0) and semi-gradient methods grow. Replace `v_π(s)` with a sample target like `R_{t+1} + γ V̂(S_{t+1}, w)` and you have an RL update; the supervised-learning scaffolding stays the same.

### Distinction From i.i.d. SL

| | Supervised Learning | RL Value Estimation |
|---|---|---|
| Data | i.i.d. samples from a fixed distribution | Sequential, correlated, **non-stationary** |
| Target | Ground-truth labels | Returns `G_t` or bootstrapped estimates `r + γ V̂(s', w)` |
| Loss | Fixed MSE on the dataset | MSE on a moving target that itself depends on `w` |
| Optimisation | Convex for linear models | Non-stationary even for linear models → only semi-gradient methods |

## Where Supervised Learning Helps RL

The slides list several ways SL complements RL. Memorise these for exam short-answers:

1. **Modelling the environment** — Learn `P(s'|s,a)` or `R(s,a)` from observed transitions when the dynamics are unknown.
2. **Value-function approximation** — Use SL regression to fit `V̂(s, w)` to observed returns (the heart of this lecture).
3. **Policy improvement from demonstrations** — Behavioural cloning / imitation learning from expert trajectories.
4. **Function approximation for Q / policy** — Neural networks as flexible Q-function or policy approximators.
5. **Transfer learning** — Reuse pre-trained features / representations from a related supervised task.
6. **Data augmentation** — Generate synthetic states / perturbations to make the agent more robust.

### Real-Life Analogy

A self-driving team might:

- Use a **supervised CNN** (trained on millions of labelled images) as the *perception module* providing features to the RL agent.
- Use **imitation learning** to bootstrap a policy from human-driver demonstrations.
- Use **SL-augmented rollouts** (slight image perturbations) to make the value function robust to lighting changes.

The RL loop still handles sequential decision-making and reward maximisation, but it leans on supervised models for everything around it.

## Mini Example: Grid-World Value Approximation

Imagine a 4×4 grid where the value of a cell is roughly "how close to the goal" you are. A linear approximation

```
V̂(s, w) = w_1 * (max_x − x) + w_2 * (max_y − y)
```

with `w_1 = w_2 = 0.5` will underestimate cells near the goal because the true value is non-linear in distance. Adding the **square** of the distance as a feature:

```
V̂(s, w) = w_1 * dx + w_2 * dy + w_3 * dx² + w_4 * dy²
```

recovers much of the true surface — illustrating both the expressiveness limitation of pure linearity and the feature-engineering escape hatch.

## Key Takeaways

- **Tabular RL breaks** in large or continuous state spaces; we replace the table with a **parameterised function** `V̂(s, w)` and learn the weights `w`.
- **Linear approximation** `V̂(s, w) = wᵀ x(s)` is simple and convex, but limited by linearity, feature engineering, and the curse of dimensionality.
- **Generalisation** is the ability to predict well on unseen states; **discrimination** in the negative sense is an ethical concept unrelated to modelling quality.
- Value estimation can be cast as **supervised regression** with the MSE loss `J(w) = E[(V̂(s,w) − v_π(s))²]`, optimised by **gradient descent** yielding `Δw = α (v_π(s) − V̂(s,w)) ∇_w V̂(s,w)`.
- RL data is **not i.i.d.** — targets depend on the agent's own evolving estimates, so naive SL is only a starting point; full RL methods (TD, semi-gradient) extend it.
- Supervised learning **complements** RL by modelling dynamics, approximating value/policy functions, enabling imitation learning, transfer, and data augmentation.
- Feature quality matters more than algorithm choice: a good `x(s)` with linear `w` often beats a poor `x(s)` with a deep network.
