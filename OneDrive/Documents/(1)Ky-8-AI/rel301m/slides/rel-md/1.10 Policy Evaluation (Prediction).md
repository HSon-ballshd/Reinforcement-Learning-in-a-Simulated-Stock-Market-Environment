# 1.10 Policy Evaluation (Prediction)

## What is Policy Evaluation?

**Policy Evaluation** (also called the *prediction* problem) is the task of computing the **state-value function** `v_π(s)` for a *given* policy `π`. Someone hands you a policy, and your job is to figure out **how good it is** — how much expected return it accumulates from every state.

This sits in contrast to **Control**, the *other* main DP task, where the goal is to *find* a policy that maximises the value function.

> **Analogy:** Policy evaluation is like predicting your GPA given the study schedule you currently follow. Control is like redesigning your study schedule to maximise your GPA. Same environment, different question.

| Task | Input | Output |
|---|---|---|
| **Prediction (Policy Eval.)** | Policy `π`, MDP model `p` | Value function `v_π` |
| **Control** | MDP model `p` | Optimal (or improved) policy `π*` |

---

## The Bellman Equation for `v_π`

For any policy `π`, the state-value function satisfies the **Bellman expectation equation**:

```
v_π(s) = Σ_a π(a|s) Σ_{s', r} p(s', r | s, a) [ r + γ v_π(s') ]
```

This is a **system of linear equations** — one equation per state. In principle you could solve it directly (e.g. matrix inversion: `v = (I - γP_π)^(-1) r`). For small MDPs that works fine, but for general/large MDPs we prefer **iterative dynamic-programming methods**.

---

## Iterative Policy Evaluation

### The Core Idea

The Bellman equation is recursive: the value of a state depends on the values of its successors. So we can use it as an **update rule** — turn the equation into iteration:

```
v_{k+1}(s) = Σ_a π(a|s) Σ_{s', r} p(s', r | s, a) [ r + γ v_k(s') ]
```

Start with an **arbitrary** initial guess `v_0` (often all zeros). Each sweep produces a new estimate `v_{k+1}` from the old one `v_k`.

### Convergence

For any initialisation `v_0`, the sequence `v_k` converges to `v_π` as `k → ∞`, provided `γ < 1` (or the MDP is episodic with termination). This is a **fixed-point** of the Bellman operator.

> **Intuition:** Each iteration is like asking every state, *"Given my current best guess of tomorrow's score, what do I think my expected exam score is from here?"* Update the answer, then ask again. After enough rounds the answers stop moving.

---

## Full-Width vs. In-Place Updates

The slides describe storing **two arrays**:

- `V(s)` — the current approximate value function.
- `V'(s)` — the updated values being written during this sweep.

### Full-Width (Two-Array) Update

Compute **all** new values using *only* the old `V`, then at the **end of the sweep** copy `V' → V`. This is what the pseudocode in Sutton & Barto looks like:

```
Repeat:
    Δ ← 0
    For each s in S:
        v ← V(s)
        V(s) ← Σ_a π(a|s) Σ_{s',r} p(s',r|s,a)[r + γ V(s')]
        Δ ← max(Δ, |v − V(s)|)
Until Δ < θ
```

### In-Place Update

A common practical variant uses a **single array**: as soon as `V(s')` is updated, subsequent states on the same sweep use the *new* value. This **converges faster in wall-clock time** (new information propagates immediately) but breaks the clean fixed-point view. Both forms converge to the same `v_π`.

| Variant | Reads from | Writes to | Convergence speed |
|---|---|---|---|
| Full-width | Old `V` | New `V'` (copied at end) | Slower per iteration |
| In-place | Mix of old + new | Same `V` | Faster (typically) |

## Worked Example: 4×4 Grid World

The slides use a classic example:

- **States:** 16 cells in a 4×4 grid.
- **Terminal states:** top-left and bottom-right corners.
- **Reward:** `r = -1` on every transition (penalty for each step).
- **Discount:** `γ = 1` (no discounting; episode ends at a terminal).
- **Actions:** `up, down, left, right`; the policy is a **uniform random** policy (`π(a|s) = 0.25`).
- **Stopping threshold:** `θ = 0.001`.

**Sweep 0:** Initialise `V(s) = 0` for all non-terminal states.

**Sweep 1:** For each cell, compute the expected value of one step: `V(s) = -1` for every non-terminal state (each step costs 1, and the immediate value of the next state is 0). Max change `Δ = 1.0`.

**Sweep 2:** Now `V` contains the cost-to-go roughly from one step away. The middle cells approach values near `-2`, corners near `-1`, etc. The wave of values propagates outward from the terminal states.

**Subsequent sweeps:** Keep going. Values spread and stabilise.

**Termination:** Stop when `max_s |V_{k+1}(s) − V_k(s)| < θ = 0.001`. The final `V` is the value function `v_π` of the random policy.

> **Visual cue:** The grid fills with negatives, deepest (most negative) far from the terminals — exactly the "shaping" you'd expect: the harder the cell is to escape from, the worse it is under a random walk.

## Algorithm Summary (Sutton & Barto Style)

**Input:** policy `π`, threshold `θ > 0`, discount `γ`.

```
Initialise V(s) = 0 for all s, V(terminal) = 0
Repeat:
    Δ ← 0
    For each s in S:
        v ← V(s)
        V(s) ← Σ_a π(a|s) Σ_{s',r} p(s',r|s,a) [ r + γ V(s') ]
        Δ ← max(Δ, |v − V(s)|)
Until Δ < θ
Output V ≈ v_π
```

This is the canonical "evaluate a policy" routine — it appears as a subroutine inside every DP **control** algorithm (policy iteration, value iteration).

## Limitations of DP

Iterative policy evaluation (and DP in general) requires:

1. **A perfect model** of the environment — the four-argument dynamics `p(s', r | s, a)`.
2. **Moderate state/action sizes** — each sweep touches every state and sums over actions. Cost is `O(|S|² · |A|)` per full sweep for tabular MDPs, which becomes intractable for huge state spaces.
3. **Markov property** — the state must summarise all relevant history.

When you don't have a model, you need **model-free** methods (Monte Carlo, TD learning) — covered in later lectures.

---

## Key Takeaways

- **Policy evaluation = prediction**: given a policy, compute its value function `v_π`. **Control** is the dual task of improving the policy.
- The Bellman expectation equation expresses `v_π` recursively and yields a **system of linear equations** that iterative DP solves.
- The **iterative policy evaluation** update rule is `v_{k+1}(s) = Σ_a π(a|s) Σ_{s',r} p(s',r|s,a)[r + γ v_k(s')]`, starting from any `v_0` and converging to `v_π`.
- **Two-array (full-width)** updates read from old `V` and write to `V'`, then swap; **in-place** updates overwrite `V` immediately and usually converge faster per sweep.
- The 4×4 grid-world example with `r = -1` and `γ = 1` shows the values propagating outward from terminal states as sweeps proceed.
- Stopping criterion: halt when the **maximum change** in any state's value is below a small threshold `θ` (e.g. 0.001).
- DP methods **require a known model** — a key limitation that motivates model-free RL.
