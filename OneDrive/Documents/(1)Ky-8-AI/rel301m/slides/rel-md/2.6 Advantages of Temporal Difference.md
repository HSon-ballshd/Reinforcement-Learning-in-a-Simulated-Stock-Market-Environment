# 2.6 Advantages of Temporal Difference (TD) Learning

Temporal Difference (TD) learning sits at the sweet spot between two classical approaches to estimating value functions: **Monte Carlo (MC)** — which learns from complete episodes — and **Dynamic Programming (DP)** — which needs a full model of the environment. This deck explains why TD is usually the workhorse choice in modern reinforcement learning.

## The Big Idea: Update After Every Move

Imagine you're learning to play chess:

- **Monte Carlo** is like playing an entire game, then reviewing every move at the end based on whether you won or lost.
- **Dynamic Programming** is like having a perfect chess oracle that tells you the exact value of every board position — but you need the oracle to know every possible response.
- **TD learning** is like updating your intuition about each position right after you make the move, using the next position's current (estimated) value as a hint.

That "update after every move" property is the heart of TD's appeal.

## Core Advantages of TD Learning

### 1. Online Learning
TD updates value estimates **after every time step**, not at the end of an episode. The agent keeps improving as it interacts with the world — essential for real-time systems like a robot walking, a trading bot, or a self-driving car reacting to traffic.

### 2. Efficiency
TD doesn't need to wait for an episode to terminate. It uses **single transitions** (or short sequences) to update:

`V(s_t) ← V(s_t) + α [ r_{t+1} + γ V(s_{t+1}) - V(s_t) ]`

Compared to MC, which must average the full return `G_t = r_{t+1} + γ r_{t+2} + ... + γ^T r_T`, this is dramatically cheaper in long episodes and large state spaces.

### 3. Bootstrapping
TD **bootstraps**: it updates a state's value using the estimate of the next state's value. This is the hybrid trick — it borrows DP's recursive structure without needing a model, and borrows MC's model-free nature without needing to finish the episode.

> Analogy: TD bootstraps the way a student uses a partially-solved problem to refine their estimate of an earlier step — they're not waiting for the professor's final answer.

### 4. Works with Incomplete Sequences
Because TD doesn't need terminal states, it handles:
- **Continuing (non-episodic) tasks**
- **Partially observable** dynamics
- Episodes that get cut off mid-trajectory

This is why TD powers most real-world RL deployments — games and robots don't always have clean endings.

### 5. Exploration / Exploitation Balance
TD's target `r_{t+1} + γ V(s_{t+1})` blends **immediate reward** with **estimated future value**. The agent naturally weights short-term vs. long-term payoffs. (MC requires explicit mechanisms like ε-greedy bolted on top.)

### 6. Model-Free
Like MC, TD learns directly from sampled experience — no need for transition probabilities `P(s'|s,a)` or reward function `R(s,a)` specified up front.

### 7. Direct Policy Improvement
Algorithms like **Q-learning** and **SARSA** learn action-values `Q(s,a)` and can directly derive an optimal policy — no separate policy-search step required.

## TD vs. Monte Carlo: The Comparison Table

| Property | **TD** | **Monte Carlo** |
|---|---|---|
| **When to update** | After every step | At episode end |
| **Online learning** | Yes | No |
| **Bootstrapping** | Yes | No |
| **Needs complete episodes?** | No (handles incomplete / continuing tasks) | Yes |
| **Bias / Variance** | Biased (uses estimates), but lower variance | Unbiased, but high variance |
| **Convergence speed** | Fast in most cases | Slow, especially with sparse rewards |
| **Model-free?** | Yes | Yes |
| **Exploration handling** | Built-in via value look-ahead | Needs ε-greedy or similar on top |

### Bias / Variance Tradeoff

```
TD(0) target:    r_{t+1} + γ V(s_{t+1})    ← biased, low variance
MC target:       G_t = Σ γ^k r_{t+k}        ← unbiased, high variance
DP target:       E_π[ r + γ V(s') ]          ← unbiased (needs model), low variance
```

- **Bias**: TD's target depends on `V(s_{t+1})`, which is initially wrong — so early updates are systematically biased. MC's return is the *actual* observed reward, so it's unbiased.
- **Variance**: MC accumulates stochasticity from many random steps → noisy targets. TD uses only one step + an estimate, so noise is much smaller.
- **Convergence**: Both converge under appropriate step-size schedules (Robbins–Monro), but TD usually converges faster in practice.

## Quick Recap of When to Use What

- **Use TD** when: data streams in continuously, episodes are long or infinite, you need fast updates, or the task is non-episodic.
- **Use MC** when: episodes are short, you have lots of computational budget, you want unbiased estimates, or you only have episodic data.
- **Use DP** when: you actually have an accurate model of the environment (rare outside small gridworlds and games).

## Real-World Domains Where TD Shines
Robotics (continuous control), game playing (TD-Gammon, AlphaZero-style self-play), finance (online portfolio updates), and natural language processing (sequential decision tasks).

## Key Takeaways

- **TD updates after every step**, giving true online, incremental learning — unlike MC, which waits for episode termination.
- **Bootstrapping** is TD's defining trick: it uses its own value estimates as targets, blending DP's recursive structure with MC's model-free sampling.
- **TD is biased but low-variance**; MC is unbiased but high-variance — both converge, but TD usually wins on speed in practice.
- TD handles **incomplete sequences** and **continuing tasks**, making it the default for most real-world RL problems.
- TD is **model-free**, removing the need for transition/reward functions that DP requires.
- Algorithms like **Q-learning** and **SARSA** build on TD to learn optimal policies directly from experience.
- Choosing between TD and MC depends on **episode length, data availability, and computational budget** — TD is usually the safer default.
