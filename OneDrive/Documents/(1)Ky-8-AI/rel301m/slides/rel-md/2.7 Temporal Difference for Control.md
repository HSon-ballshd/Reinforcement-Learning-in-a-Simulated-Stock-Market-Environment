## From Prediction to Control: GPI with TD

**Generalized Policy Iteration (GPI)** is the umbrella idea behind almost every RL control method: keep alternating between two steps until convergence.

1. **Policy evaluation** — estimate the value of the current policy.
2. **Policy improvement** — make the policy greedier with respect to those estimates.

What TD gives us is a fast, online way to do step 1 without waiting for an episode to finish.

### Monte Carlo vs TD for Control

| Aspect | Monte Carlo Control | TD Control |
|---|---|---|
| Evaluation step | Full episode rollout, then update | Single step, then update |
| Improvement trigger | End of every episode | After every single transition |
| Bootstraps? | No (uses actual return $G_t$) | Yes (uses an estimate) |
| Needs episode to end? | Yes | No — works in continuing tasks |

The big insight: **we don't need a perfect value estimate before improving the policy**. Even after one TD step, the estimate is good enough to nudge the policy a little. This is exactly the "generalized" in GPI — we never need to fully converge the inner loop.

## SARSA — State-Action-Reward-State-Action

SARSA is the canonical **on-policy TD control** algorithm. The name is a mnemonic for the tuple of data it uses every step:

> **S**tate → **A**ction → **R**eward → **S**tate → **A**ction

Because it learns about the *same* policy it is currently executing, it is **on-policy**. (Compare this to Q-learning, which is off-policy — covered in the next lecture.)

### What SARSA Learns

SARSA learns the **action-value function** $Q(s, a)$ — the expected cumulative reward from taking action $a$ in state $s$ and then following the current policy thereafter:

`Q(s, a) ≈ E[ G_t | S_t = s, A_t = a ]`

### The SARSA Update Rule

```
Q(S, A) ← Q(S, A) + α [ R + γ Q(S', A') − Q(S, A) ]
```

Where:

- `α` (learning rate): step size for the update, e.g. 0.1.
- `γ` (discount factor): weight on future rewards, 0 ≤ γ < 1.
- `R + γ Q(S', A')` is the **TD target** — a bootstrapped estimate of return.
- `R + γ Q(S', A') − Q(S, A)` is the **TD error** `δ_t`, the surprise signal driving learning.
- `A'` is the action actually taken in `S'` under the *current* policy (this is what makes SARSA on-policy).

Notice `A'` must be chosen **using the same ε-greedy rule** that produced `A` — if you sneak in a max over actions here, you've accidentally written Q-learning.

### ε-Greedy Action Selection

To keep exploring while exploiting, use an ε-greedy policy:

```
A ← argmax_a Q(S, a)         with probability 1 − ε
A ← random action            with probability ε
```

Typical ε-schedule: start high (e.g. 1.0) and decay toward a small floor (e.g. 0.05) so exploration tapers off as Q becomes reliable.

## The SARSA Algorithm (Pseudocode)

**Initialization**
- Initialize `Q(s, a)` arbitrarily for all state-action pairs (often zeros).
- Set ε, α, γ.

**For each episode:**
1. Initialize `S` (the starting state).
2. **Choose `A` in `S`** using ε-greedy from current Q.
3. **Repeat** for each time step:
   - Take action `A`, observe `R` and next state `S'`.
   - **Choose `A'` in `S'`** using ε-greedy from current Q.
   - **Update:**
     `Q(S, A) ← Q(S, A) + α [ R + γ Q(S', A') − Q(S, A) ]`
   - `S ← S'`, `A ← A'`.
4. Until `S` is terminal.

A handy mnemonic: **"You need to know the consequence of your next action before you can update the current one."** That is, the update uses `(S, A, R, S', A')` — the whole quintuple.

## Worked Sketch: SARSA in `FrozenLake-v0`

The slides walk through a code example using OpenAI Gym's `FrozenLake-v0` (the classic 4×4 grid where the agent must walk from Start to Goal without falling into holes). The structure mirrors the pseudocode above:

1. Import `gym` and `numpy`.
2. Build the environment: `env = gym.make('FrozenLake-v0')`.
3. Initialize hyperparameters (`alpha`, `gamma`, `epsilon`, `num_episodes`).
4. Define utility helpers — typically `choose_action(Q, state, epsilon)` for ε-greedy selection and `update_q(Q, s, a, r, s_next, a_next, alpha, gamma)` for the SARSA step.
5. Train: run episodes, sample `(s, a, r, s', a')` tuples, apply the update, decay ε over time.
6. Evaluate: roll out the learned ε-greedy (or greedy) policy and report the fraction of successful reaches to the Goal.

FrozenLake is small and stochastic, so it nicely illustrates why **on-policy** methods matter — the agent has to learn a path that is robust to the slippery transitions, not just the deterministic best path.

## On-Policy vs Off-Policy (at a glance)

| | SARSA (on-policy) | Q-learning (off-policy) |
|---|---|---|
| Next-action term | `Q(S', A')` where `A'` is sampled by ε-greedy | `max_a Q(S', a)` |
| What it learns | Value of the **behavior policy** (including exploration noise) | Value of the **greedy / target policy** |
| Robust to risky exploration? | Yes — penalizes risky paths the agent might stumble into | No — assumes it can act optimally regardless of ε |

In short: SARSA learns the value of the policy it actually follows, exploration noise and all. Q-learning pretends exploration noise doesn't exist.

## Real-Life Analogies

1. **Commuting by bike vs by taxi.** SARSA is like a cyclist who re-routes based on roads they themselves can ride (on-policy, sensitive to vehicle capability). Q-learning is like a navigation app that recommends the absolute fastest route assuming you drive a sports car — great on paper, useless in the rain.
2. **The "remember the consequence" joke.** Why is it called SARSA? Because the algorithm has to remember what action it *actually* took next (`A'`), not what it *wished* it had taken. Forget `A'` and you've turned it into Q-learning — and your exam answer is wrong.
3. **Learning to cook on a budget.** MC control = wait until the end of the month to see how your budget went, then adjust. TD/SARSA = each time you buy groceries, immediately update your mental estimate of "how much have I spent so far?" and adjust the next purchase. Faster feedback, less regret.

## Key Takeaways

- **GPI + TD = fast online control.** You don't need a full evaluation pass — improve the policy after every single TD step.
- **SARSA is the on-policy TD control algorithm.** It learns `Q(s, a)` directly using the quintuple `(S, A, R, S', A')`.
- **The update is `Q(S,A) ← Q(S,A) + α[R + γ Q(S',A') − Q(S,A)]`**, where `A'` is chosen by the *same* ε-greedy policy.
- **ε-greedy** balances exploration and exploitation; typically ε is decayed over training.
- **On-policy vs off-policy** matters: SARSA includes the cost of exploration noise in its value estimates, making it safer in risky environments (e.g. cliff walking).
- **No episode termination required** — unlike MC control, SARSA can run on continuing tasks because it bootstraps.
- **Hyperparameters α, γ, ε and their schedules** drive almost all of SARSA's empirical behavior; tune them before blaming the algorithm.
