# 3.12 Policy Parameterizations

In tabular RL we store one Q-value per state–action pair. In real problems the state/action space is too large, so we **parameterize** the policy with weights `θ` and learn those weights instead. This deck covers the two workhorse parameterizations: **softmax policies for discrete actions** and **Gaussian policies for continuous actions**, both used inside Actor-Critic.

## Actor-Critic with Softmax Policies

### Setup

Recall Actor-Critic splits the work:
- The **critic** estimates the value function using **semi-gradient TD** (the "semi" because the target uses a bootstrap estimate that is itself parameterized).
- The **actor** uses the **TD error** (TDR) returned by the critic as a low-variance signal to update the policy parameters `θ`.

The actor does not need to roll out an entire episode; it reacts to one-step feedback from the critic each tick.

### Softmax Policy Definition

For discrete actions we define a preference (or "score") for every (state, action) pair and turn scores into probabilities with a **softmax**:

```
π(a | s, θ) = exp(h(s, a, θ)) / Σ_b exp(h(s, b, θ))
```

The **action preference function** `h(s, a, θ)` is the actor's parameterized brain. A common choice is **linear preferences**:

```
h(s, a, θ) = θᵀ x(s, a)
```

where `x(s, a)` is a hand-crafted (or learned) feature vector concatenating state and action indicators. Each weight in `θ` says how much that feature pushes the agent toward (or away from) action `a`.

**Intuition:** softmax makes the probability of an action **proportional to its preference**. If action "turn left" scores 5 and "turn right" scores 1, left is roughly `e^5 / (e^5 + e^1) ≈ 0.982` — almost certain, but not absolute. The exp/zeros-out-bad-options smoothly interpolates between greedy and uniform-random.

> **Joke:** softmax is the indecisive friend who says "I'll mostly do my favorite thing, but I'll still show up to the other options so nobody feels left out."

### Stacked State Features

A nice trick: stack all the per-action weight vectors into one matrix `Θ` whose rows correspond to actions, and write the preference as `h(s, a, θ) = Θ[a] · x(s)`. Then the softmax over `a` becomes a single vectorized operation.

### Update Equations (from the algorithm slide)

Using `δₜ = R_{t+1} + γ · v̂(S_{t+1}, w) − v̂(Sₜ, w)`:

```
θ  ←  θ + α_θ · δₜ · ∇ln π(Aₜ | Sₜ, θ)     (actor)
w  ←  w + α_w · δₜ · ∇v̂(Sₜ, w)             (critic, semi-gradient)
```

For linear preferences `h(s, a, θ) = θᵀ x(s, a)`, the policy gradient has a clean closed form:

```
∇ln π(a | s, θ) = x(s, a) − Σ_b π(b | s, θ) · x(s, b)
```

i.e. **features of the chosen action minus the expected features under the current policy**. This is the "centered" version that prevents weight drift.

## Gaussian Policies for Continuous Actions

When actions live on the real line (steering angles, torques, throttle), we cannot sum over a finite set — we need a **density over `ℝ`**.

### Definition

A Gaussian policy treats each action as a sample from a Normal distribution whose mean and variance depend on the state:

```
a ~ N(μ(s, θ), σ²(s, θ))
π(a | s, θ) = (1 / √(2π σ²)) · exp(−(a − μ)² / (2 σ²))
```

- **μ(s, θ)** — the mean — can be **any parameterized function** (e.g. a linear layer, a neural net). It encodes "what to do" in state `s`.
- **σ²(s, θ)** — the variance — **must be positive**. The simplest valid choice is `σ² = exp(linear(s, θ))` so the network outputs a log-standard-deviation.
- The full parameter vector is `θ = (θ_μ, θ_σ)`.

> **Analogy:** think of μ as the thermostat dial that you actually want to set, and σ as how much the dial wiggles on its own. A big σ = "I'll experiment around this setting"; a small σ = "I'll commit to it."

### Log-Derivative (needed for the policy gradient theorem)

For the Gaussian policy, the gradient of the log-probability decomposes neatly:

```
∇_θ ln π(a | s, θ) = ∇_θ ln σ + ((a − μ) / σ²) · ∇_θ μ
```

(Simplified for the case where μ and σ are separate parameter blocks.)

### Why σ Matters

- **Large initial σ** → wide action distribution → lots of **exploration** early in training.
- **Small σ** → narrow, near-deterministic policy → **exploitation** late in training.
- A common heuristic: parameterize `log σ` and anneal it, or even let it be learned.

## Why Bother with Continuous Actions?

Discrete action sets force you to pre-chop the action space — fine for "buy/sell/hold" but disastrous when steering by 0.1° vs 0.2° actually matters. Continuous policies give you:

- **Expressiveness** — fine-grained control (e.g. torque on a robot joint).
- **Smoothness** — neighboring action values produce neighboring behavior; no cliffs.
- **Efficiency of exploration** — gradient info tells you which *direction* in action space improves things.
- **Generalization** — nearby actions share probability mass; you don't waste samples re-estimating each of 10,000 discretized bins.
- **Optimization-friendly** — the log-derivative is analytic, so vanilla policy-gradient and actor-critic methods just plug in.

### Pseudocode Skeleton

```python
for each step t:
    δ = r + γ * v(s_next, w) - v(s, w)        # critic TD error
    w += α_w * δ * ∇v(s, w)                   # critic update
    θ_μ += α_θ * δ * (a − μ(s)) / σ² * ∇μ(s) # actor μ-update
    θ_σ += α_θ * δ * ((a−μ)² − σ²) / σ² * ∇σ  # actor σ-update
    a = sample_from_N(μ(s_next, θ_μ), σ(s_next, θ_σ))
```

## Key Takeaways

- **Softmax policy**: turns linear preferences `h(s,a,θ)=θᵀx(s,a)` into action probabilities — a discrete-action parameterization that pairs naturally with Actor-Critic.
- **Actor-Critic split**: the **critic** does semi-gradient TD on the value function; the **actor** uses the critic's TD error as the scalar "goodness" signal for a policy-gradient update.
- **Gaussian policy**: parameterized continuous actions via `a ~ N(μ(s,θ), σ²(s,θ))`; σ must stay positive (often via `exp(·)`) and governs exploration.
- **Log-derivative trick**: both softmax and Gaussian policies give closed-form `∇ln π`, which is why policy-gradient methods need only a single sampled action per update.
- **Exploration vs exploitation** is controlled in the softmax case by the *spread* of preferences, and in the Gaussian case by σ — typically initialized large and decayed.
- **Continuous actions win** when you need precision, smoothness, or gradient-based optimization across action space; discrete softmax wins when actions are naturally categorical.
- **Practical tip**: parameterize `μ` and `log σ` separately with two heads of a network; this keeps σ strictly positive and makes the log-gradient numerically stable.
