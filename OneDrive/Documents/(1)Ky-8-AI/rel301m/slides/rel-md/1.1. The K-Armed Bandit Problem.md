# 1.1 The K-Armed Bandit Problem

The classic "Hello, World!" problem of reinforcement learning. Single state, no dynamics — just pure **exploration vs. exploitation** decision-making under uncertainty.

---

## What is Reward?

**Reward** is a scalar feedback signal provided by the environment to the learning agent at a particular state and time step. It is the primary mechanism that shapes the agent's behavior and tells it how well it is performing.

- Scalar (single number, e.g., +1, -1, 0.5, etc.)
- Depends on the current state and the action taken
- The agent's job: learn a policy that **maximizes cumulative reward** (or expected return)

> **Real-life example:** A Roomba vacuum receives a small positive reward each time it picks up dirt, a small negative reward for bumping into furniture, and zero otherwise. Those scalars are what train its behavior.

---

## The Bandit Problem (Intuition)

Imagine a gambler standing in front of a row of **slot machines** (one-armed bandits). Each machine has an **unknown probability distribution** of paying out. The gambler gets a fixed budget of pulls and wants to maximize total winnings.

This is exactly the **k-armed bandit** setting:

- There are **k** actions (arms) to choose from at every step.
- Each action a delivers a reward drawn from an unknown distribution R(a).
- After each pull, you observe the reward, then choose again. The game repeats.

> **Why is it hard?** You don't know which machine is best. So you face a trade-off: should you keep pulling the arm that has paid out well so far, or try others that might be even better?

---

## Exploration vs. Exploitation

This is the **central tension** of the bandit problem — and of most RL.

- **Exploitation:** Choose the action that, based on past experience, seems to give the highest reward. (Play it safe, milk the known good arm.)
- **Exploration:** Try other, less-tried arms to learn more about their reward distributions. (Risk a short-term loss for potentially discovering a better arm.)

If you only exploit, you might miss the best machine. If you only explore, you waste pulls on bad arms. A good bandit algorithm **balances both**.

### Real-life examples

- **New coffee shop in town:** You have a favorite cafe, but there are 9 others you've never tried. Do you keep going to your usual (exploit) or try a new one this week (explore)?
- **A/B testing a website:** You have a button that converts at 8%. A new design might convert at 12%. How long do you keep showing the old one before switching? Pure exploitation = leave it; pure exploration = flip a coin forever.
- **Clinical trials (the doctor case in the slides):** A doctor has three treatments (blue, red, yellow). The "reward" is the patient's welfare. The doctor must learn which works best while treating real patients.

## Formal Definition: k-Armed Bandit

At each time step t:

1. The agent observes the current situation (in the basic case, just a single starting state).
2. The agent selects an action `A_t` from {1, 2, ..., k}.
3. The environment returns a reward `R_{t+1}`.
4. The episode **terminates** (or repeats with the same state).

**Key property:** In the *stationary* bandit problem, the action chosen does **not affect the next observation**. There are no state transitions, no dynamics. Each pull is an independent sample.

This makes bandits the **simplest non-trivial sequential decision problem** — a great warm-up before tackling full Markov Decision Processes (MDPs).

---

## Action-Values (Action-Value Function)

To decide which action is best, the agent needs a notion of **how good each action is**. That notion is the **action value** (a.k.a. the action-value function), denoted `q*(a)`.

### Definition

```
q*(a) = E[ R_t | A_t = a ]
```

That is: the **expected reward** if you take action `a`. In expanded form, as a sum over possible reward values:

```
q*(a) = sum over all possible rewards r of:  r * p(r | a)
```

In words: multiply each possible reward by the probability of seeing that reward, and sum.

> **The "doctor" example in the slides:** A doctor chooses between blue, red, and yellow treatments. The action value of, say, "red treatment" is the expected patient welfare if red is prescribed. The treatment that maximizes q*(a) is the optimal one.

### Estimating action values from samples

Since the true `q*(a)` is unknown, the agent must **estimate** it from observed rewards. The simplest estimator is the **sample average**:

```
Q_t(a) = (sum of rewards when a was chosen up to time t) / (number of times a was chosen up to time t)
```

If action `a` was chosen `N_t(a)` times and yielded rewards r_1, r_2, ..., r_{N_t(a)}, then:

```
Q_t(a) = (1 / N_t(a)) * sum_{i=1..N_t(a)} r_i
```

By the law of large numbers, `Q_t(a) → q*(a)` as `N_t(a) → ∞`. A natural (greedy) policy is to always pick the action with the **highest current estimate**:

```
A_t = argmax_a Q_t(a)
```

This is the **greedy** rule. Pure greedy = pure exploitation. To inject exploration, you can act greedily **most of the time** but occasionally (with probability ε) pick a random arm — that's the **ε-greedy** algorithm, covered in the next section.

---

## Quick-Worked Example

Suppose a treatment has:
- 30% chance of success, giving reward = +10
- 70% chance of failure, giving reward = 0

Then:

```
q*(treatment) = (0.3 * 10) + (0.7 * 0) = 3
```

So on average, that treatment yields a reward of 3. The doctor should prefer it over a treatment whose expected reward is, say, 1.5.

---

## Key Takeaways

- A **reward** is a scalar feedback signal from the environment that drives learning.
- The **k-armed bandit** is a row of k actions, each with an unknown reward distribution; pick one per step, get a reward, repeat.
- The central challenge is the **exploration–exploitation trade-off**: try new arms to learn, or stick with the current best.
- The **action-value** of an action `a` is its expected reward, `q*(a) = E[R_t | A_t = a]`.
- In practice the agent estimates q*(a) using the **sample average** `Q_t(a)`, which converges to the true value as more samples are gathered.
- Bandits have **no state dynamics** — the chosen action does not change the next observation. This makes them the simplest RL setting and a building block for full MDPs.
- Real applications: clinical trials, online advertising (A/B/n testing), adaptive routing, hyperparameter tuning, and recommendation systems.
