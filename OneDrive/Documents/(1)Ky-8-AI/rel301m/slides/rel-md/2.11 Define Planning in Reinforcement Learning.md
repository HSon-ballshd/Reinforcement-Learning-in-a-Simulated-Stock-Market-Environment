# 2.11 — Planning in Reinforcement Learning

## What is Planning?

**Planning** in RL is the process of taking a **model** of the environment as input and using it to produce or improve a policy. The key idea: instead of (or in addition to) learning from real interactions with the world, the agent **simulates experience** inside its head and uses that simulated experience to update its value function and policy.

> **Analogy:** Imagine you're standing at a crossroads. Before walking, you mentally picture each route — "if I go left, I'll reach the bakery; if I go right, I'll get to the park." That mental rehearsal is planning. In RL, the agent does the same thing, but with numbers instead of mental images.

> **Chess example:** When a chess player thinks three moves ahead, they're running a tiny simulation in their head. They're not actually moving pieces — they're using their internal *model* of chess to predict outcomes and pick a better move. That's planning in action.

### The Core Distinction

| Approach | Learns from | Requires a model? |
|---|---|---|
| **Model-free RL** (e.g., Q-learning, SARSA) | Real experience | No |
| **Planning** (model-based) | Simulated experience | Yes |

Planning is essentially **decision-time computation**: using a model to compute better decisions.

## Random-Sample One-Step Tabular Q-Planning

This is the canonical planning algorithm (Sutton & Barto, Ch. 8). It mirrors Q-learning, but the "experience" is drawn from a **sample model** rather than the real environment.

**Algorithm sketch:**

1. **Sample** a state–action pair `(S, A)` at random from the set of all states and actions.
2. **Query** the sample model with `(S, A)` to produce a sample of the next state `S'` and reward `R`.
3. **Perform a Q-learning update** on this model-generated transition:

```
Q(S, A) ← Q(S, A) + α [ R + γ · max_a Q(S', a) − Q(S, A) ]
```

4. **Improve the policy** by acting greedily with respect to the updated action values.

**Key properties:**

- Planning uses **only imagined / simulated experience** — no real interaction required for the update.
- Updates can be done **off-policy** (the data comes from the model, not from the agent's current behaviour).
- Can run **in parallel** with the real interaction loop, or completely offline ("pure planning").

## Distribution Models vs. Sample Models

The slides distinguish between two kinds of models a planner can use:

- **Distribution model:** gives the full probability distribution `p(s', r | s, a)` over next states and rewards. With it, you can compute **expected** values exactly (e.g., `R + γ · Σ_s' P(s'|s,a) · max_a Q(s', a)`).
- **Sample model:** produces a **single sample** `(s', r)` drawn from that distribution. Planning algorithms like random-sample Q-planning use this — it's cheaper and works well in practice because the learning process itself averages over many samples.

> Practical tip: in large state spaces the distribution model is intractable, so most modern RL planners (e.g., Dyna, MCTS) use **sample models**.

## How Planning Works in RL — The Pipeline

1. **Model Representation** — Have (or learn) a model `p(s', r | s, a)` that describes environment dynamics and rewards.
2. **Simulation** — Use the model to simulate sequences of states/actions, predicting consequences **without touching the real environment**.
3. **Action Selection** — Choose actions that maximize expected reward / minimize cost / hit some goal.
4. **Policy Improvement** — Update the value function and policy from the simulated outcomes.
5. **Execution** — Deploy the chosen actions in the real world, observe real outcomes, and use them to refine the model and future plans.

> **Joke:** "Why did the RL agent fail its driving test? It kept planning what it *would* do, but never actually *did* anything." Planning only pays off when you eventually act on it.

## Planning vs. Learning

- **Learning** = improving the policy from **real** experience.
- **Planning** = improving the policy from **simulated** experience.
- They use the **same underlying machinery** (e.g., Q-learning-style backups). The only difference is the *source* of the `(S, A, R, S')` transitions.

This is the central insight of the **Dyna architecture** (covered in later lectures): interleave real learning steps with planning steps that reuse the same update rule on model-generated data.

## Real-Life Examples

- **Self-driving car:** Before changing lanes, the car simulates "what if I move left now?" against its learned model of nearby traffic — that's planning.
- **Game-playing AI (AlphaGo):** Runs Monte Carlo Tree Search, simulating thousands of future board positions before picking a move.
- **Robot vacuum:** Mentally tries a few candidate paths around a new obstacle, then commits to the best one.

## Key Takeaways

- **Planning** uses a model to simulate experience and improve the policy — it is *decision-time computation*.
- **Random-sample one-step tabular Q-planning** samples `(S, A)`, queries a sample model for `(S', R)`, then applies a standard Q-learning backup.
- Planning relies on **simulated (imagined) transitions**, not real ones, and can run in parallel with or entirely separate from real interaction.
- A **distribution model** gives full transition probabilities; a **sample model** returns single draws — most planners use the latter for scalability.
- The full planning pipeline is: **model → simulate → select action → improve policy → execute**.
- Planning and learning share the same update machinery; only the **source of experience** differs.
- Planning is the foundation of model-based methods like **Dyna** and **MCTS** — both are essential for sample-efficient RL.
