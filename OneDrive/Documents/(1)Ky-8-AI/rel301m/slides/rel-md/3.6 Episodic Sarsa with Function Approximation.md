# 3.6 Episodic Sarsa with Function Approximation

## From State Values to Action Values

So far in function approximation we learned a value function `V̂(s, w)` whose output is a single number per state. To do **control** we need a function that scores every **state–action** pair: `Q̂(s, a, w)`.

Conceptually nothing exotic changes — we still take a dot product of a weight vector and a feature vector:

```
Q̂(s, a, w) = w^T x(s, a)
```

The trick is that the **feature vector must now represent actions too**. There are two common ways to do this.

---

## Action-Dependent Feature Construction

### 1. Stacked (one-hot-of-actions) features

Suppose we have 4 state features and 3 actions. We build a feature vector of length `4 × 3 = 12` by concatenating the state features for every action:

```
x(s, a) = [ φ(s)·𝟙{a=0} ,  φ(s)·𝟙{a=1} ,  φ(s)·𝟙{a=2} ]^T
```

Only the segment corresponding to the chosen action is non-zero; the other segments are zeroed out. The matching weight vector is also split into 3 segments — we say the weights are **stacked on top of each other**, one column per action. Each action effectively gets its own linear function over the state features.

> **Analogy** — think of three parallel index cards, one per action. You only write on the card that matches the action you took; the others stay blank. Learning each action's value is independent of the others, but they all share the same state features.

### 2. Neural-network action values

Two popular architectures:

- **Multiple outputs**: the network takes the state as input; the last hidden layer produces state features, then **separate linear heads** output one Q-value per action.
- **Single output**: input is `(state, action)` (concatenated or one-hot), network outputs a single `Q̂(s, a)`. Tiling-coding can do the same thing by passing the action index as an extra input dimension.

---

## The Episodic Semi-Gradient Sarsa Update

This is the core result of the lecture. For each transition `(S_t, A_t, R_{t+1}, S_{t+1}, A_{t+1})`, after observing the next action actually taken:

```
w_{t+1} ← w_t + α [ R_{t+1} + γ Q̂(S_{t+1}, A_{t+1}, w) − Q̂(S_t, A_t, w) ] · ∇Q̂(S_t, A_t, w)
```

Key points:

- It is a **semi-gradient** method — the target `R + γ Q̂(...)` is treated as fixed when differentiating, so we ignore `∇Q̂(S_{t+1}, A_{t+1}, w)`.
- The **TD error** `δ_t = R_{t+1} + γ Q̂(S_{t+1}, A_{t+1}, w) − Q̂(S_t, A_t, w)` drives the update.
- With linear FA (`Q̂ = w^T x`), `∇Q̂ = x(s,a)`, so the update collapses to the familiar linear form:
  ```
  w ← w + α δ · x(S_t, A_t)
  ```
- This is **on-policy**: the next action `A_{t+1}` must come from the same (ε-greedy) policy used to pick `A_t`.

## Mountain Car — The Canonical Example

Mountain Car is the classic **underpowered-engine** problem: a car sits in a valley between two hills and its engine is too weak to drive straight up either slope. No matter how hard it accelerates, gravity pulls it back down.

The only way to reach the goal flag at the top of the right hill is to **first swing backwards up the left hill, gain potential energy, then accelerate forward** to build enough momentum to crest the right side. This is exactly the kind of non-greedy, long-horizon credit-assignment problem where function approximation + Sarsa shines:

- The state is continuous (position, velocity), so a tabular approach explodes — we need **tile coding or a coarse feature vector**.
- The reward is `-1` per step until the goal, so the agent must learn that "going away from the flag now" is sometimes the best move.
- The stacked-features trick with a small number of tilings lets Sarsa learn a smooth value landscape over `(position, velocity)` and discover the swing-back policy.

> **Joke** — Mountain Car is what happens when you buy the cheapest Tesla trim and try to climb Pikes Peak in winter. The fix isn't more throttle; it's learning to roll downhill first.

## From Sarsa → Expected Sarsa → Q-Learning

All three are TD-style control algorithms. They differ only in **how they value the next state**:

| Algorithm | Next-state value |
|---|---|
| **Sarsa** | `Q̂(S_{t+1}, A_{t+1}, w)` — sample one action actually taken |
| **Expected Sarsa** | `Σ_a π(a\|S_{t+1}) · Q̂(S_{t+1}, a, w)` — expectation under target policy |
| **Q-Learning** | `max_a Q̂(S_{t+1}, a, w)` — greedy max |

### Expected Sarsa update

```
w ← w + α [ R + γ Σ_a π(a|S') Q̂(S', a, w) − Q̂(S, A, w) ] · ∇Q̂(S, A, w)
```

Because Expected Sarsa uses the full expectation rather than a single noisy sample, it **reduces variance** at the cost of one extra dot-product per action in the next state. With a tabular representation it is equivalent to Sarsa in expectation.

### Q-Learning update

```
w ← w + α [ R + γ max_a Q̂(S', a, w) − Q̂(S, A, w) ] · ∇Q̂(S, A, w)
```

Same target as tabular Q-learning but the bootstrap uses the approximated action values. **Important caveat with FA**: Q-learning is no longer guaranteed to converge once we leave the tabular world. Off-policy + bootstrapping + function approximation = the deadly triad — without fixes (target networks, Double DQN, etc.) it can diverge.

---

## Convergence Notes (with Linear FA)

- **Sarsa with linear FA and on-policy data converges** under the usual Robbins-Monro step-size conditions and sufficient exploration (any policy visiting all state-action pairs infinitely often). The fixed point is the TD solution of the on-policy distribution.
- **Expected Sarsa** enjoys the same convergence guarantee because the expectation removes sampling noise.
- **Q-learning with linear FA does NOT, in general, converge** — the deadly triad issue. This is one of the most common exam traps: students remember "Q-learning converges" from the tabular chapter and forget it doesn't carry over.

## Worked Intuition: Grid-World Sarsa Walk-through

The deck's Sarsa example walks a small grid world where the agent updates Q-values after every `(S, A, R, S', A')` step. With function approximation, each grid cell (and each action in that cell) maps to a small feature vector; the update nudges weights in the direction of `δ · x(s,a)`. After many episodes the dot products reproduce the true action values well enough that ε-greedy action selection becomes near-optimal.

---

## Key Takeaways

- **Action-dependent features** can be built by *stacking* state features per action, by using a neural net with one output per action, or by feeding `(state, action)` into a single-output net.
- The **episodic semi-gradient Sarsa update** is `w ← w + α [R + γ Q̂(S', A', w) − Q̂(S, A, w)] · ∇Q̂(S, A, w)`; with linear FA this becomes a simple `αδx` rule.
- **Sarsa, Expected Sarsa, and Q-learning** differ only in how they evaluate the next state — sample, expectation, or max.
- **Expected Sarsa lowers variance** vs. plain Sarsa at the cost of evaluating all next-state actions.
- Under **linear FA**, on-policy Sarsa and Expected Sarsa converge; off-policy Q-learning is **not** guaranteed to converge — watch out for the deadly triad on exams.
- **Mountain Car** is the canonical continuous-state FA control benchmark; the underpowered-engine analogy makes it memorable.
- Remember: tabular guarantees do **not** transfer automatically — function approximation changes everything from update rules to convergence proofs.
