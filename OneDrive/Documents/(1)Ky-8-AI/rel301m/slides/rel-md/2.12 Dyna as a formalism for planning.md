# Dyna as a Formalism for Planning — Study Notes

## What is Dyna?

**Dyna** is a unified reinforcement learning architecture introduced by **Richard S. Sutton in 1990**. It is a *hybrid* approach that fuses **model-based planning** with **model-free learning**, letting an agent get the best of both worlds: it learns a policy directly from real interaction **and** sharpens that policy using simulated experience derived from a learned model of the environment.

> **Analogy — playing chess by day, studying your own games by night.** Every "real" move you make in an actual game is like a real-environment step (model-free RL update). Every evening when you sit at the board and replay past positions, asking "what if I had played differently?" — that is the planning half. Dyna is the player who does *both*, every single day.

---

## The Dyna Architecture

The architecture is built from five cooperating components, all running off the same stream of experience:

1. **Environment and policy** — generate real experience `(S, A, R, S')`.
2. **Direct RL** — use that experience to update value estimates (e.g., Q-learning).
3. **Model learning** — observe transitions and rewards, and build an internal model `Model(S, A) → (R, S')`.
4. **Search control** — choose which states the agent should "hallucinate" about during planning.
5. **Planning** — sample `(s, a)` from the search-control set, ask the model for a simulated `(r, s')`, and run another RL update on that simulated transition.

The architectural diagram is best read as **one big loop** where every real step is also a *seed* for `n` additional simulated steps. This is sometimes called the **real experience + daydreaming** idea of Dyna.

### Why integrate planning with model-free learning?

- **Sample efficiency** — every real interaction gives rise to many synthetic ones, so fewer real samples are needed.
- **Generalization** — the model lets the agent reason about states it has never visited.
- **Faster adaptation** — when the world changes, a learned model can be updated cheaply and the planning loop reuses it immediately.

## Tabular Dyna-Q (Algorithm)

In the **tabular** setting, the model is just a lookup table. The pseudocode below is the canonical **Tabular Dyna-Q** algorithm (Sutton & Barto, *Reinforcement Learning: An Introduction*, Ch. 8):

```
Initialize Q(s, a) and Model(s, a) for all s ∈ S, a ∈ A(s)
Do forever:
    (a)  S ← current (nonterminal) state
    (b)  A ← ε-greedy(S, Q)
    (c)  Execute A; observe R, S'
    (d)  Q(S, A) ← Q(S, A) + α · [ R + γ · max_a Q(S', a) − Q(S, A) ]   # direct RL
    (e)  Model(S, A) ← R, S'                                          # model learning
    (f)  Repeat n times:
            S ← random previously observed state
            A ← random action previously taken in S
            R, S' ← Model(S, A)                                       # simulated step
            Q(S, A) ← Q(S, A) + α · [ R + γ · max_a Q(S', a) − Q(S, A) ]   # planning update
```

Key things to notice:

- Step **(d)** is plain **Q-learning** on real data.
- Step **(e)** is **deterministic tabular model learning** — just remember the last `(R, S')` you saw for `(S, A)`.
- Step **(f)** is the **planning loop**. The hyperparameter **`n`** controls how many simulated updates happen per real one. `n = 0` collapses Dyna back into vanilla Q-learning; large `n` gives heavy model-based rehearsal.
- The planning update uses the **same Q-learning rule** — Dyna is model-free at heart; the model only *generates transitions*.

> **Analogy — studying with flashcards.** Real lecture attendance = direct RL (one update per class). Re-reading notes at home = planning (n updates per class). Bigger `n` is like a student who spends more evenings reviewing.

## Dyna vs Pure Q-Learning

This is a frequent exam question. Here is the side-by-side:

| Aspect | **Q-learning (model-free)** | **Dyna (model + planning)** |
|---|---|---|
| **Model learning** | None — no explicit transition/reward model is stored. | Learns `Model(s, a) → (r, s')` from every real step. |
| **Use of experience** | One Q-update per real transition. | One Q-update per real transition **plus `n` planning updates**. |
| **Planning** | Absent. Actions are picked by the policy; values come from observed data. | Plans by *simulating* trajectories through the learned model. |
| **Exploration** | Relies on external strategy such as **ε-greedy**. | The simulated rollouts themselves explore counterfactual actions; still typically combined with ε-greedy on the real policy. |
| **Sample efficiency** | Lower — needs many real samples, especially in large stochastic envs. | Higher — synthetic samples amortize real experience. |
| **Stability** | Updates depend only on observed data; can be noisy in high-variance environments. | Mixed real + simulated updates can be **more stable** when the model is accurate, but can be **biased** if the model is wrong. |
| **Implementation complexity** | Simple — one Q-table, one update rule. | More complex — table of `(s, a)` outcomes, search-control logic, planning loop. |

The single most important sentence to memorize:

> **Dyna is identical to Q-learning, except that after each real-environment update it also performs `n` additional Q-learning updates on transitions drawn from a learned model.**

## Advantages (exam-ready)

- **Improved sample efficiency** — reduces the need for expensive real-world exploration.
- **Better generalization** — the model generalizes beyond states the agent has actually visited.
- **Faster learning** — combines the strengths of model-based and model-free methods.
- **Stability** — averaging real and simulated updates smooths high-variance targets.

## Limitations / Pitfalls

- **Model bias** — if the learned model is wrong (e.g., deterministic in a stochastic env), planning amplifies the error. This is the well-known **model-bias** problem.
- **Computational cost** — each real step triggers `n` extra updates.
- **Search-control design** — naive uniform sampling of states is often wasteful; smarter heuristics focus planning on recently visited or high-error states.

## Real-World Examples & Jokes

1. **Chess coaching (already used above).** Real games = direct RL; reviewing and analyzing past games with an engine = planning. The coach's "model" is their accumulated theory of openings.
2. **Driving school with a simulator.** Real road hours are limited and expensive; an instructor adds hours in a driving sim that mirrors the city. The sim is the *learned model*, the real road is the *environment*.
3. **Why Dyna sometimes fails (a joke with teeth).** A self-driving car learns a model of how pedestrians walk — but one day someone rides a scooter. The model confidently *plans* "pedestrians don't ride scooters", so the car never updates that belief from real experience quickly enough. **Garbage in, confident garbage out.** Dyna is only as good as its model.

---

## Key Takeaways

- **Dyna** = one real Q-learning update + `n` simulated Q-learning updates per environment step, all using the same Q-function.
- The five components are: **direct RL, model, model learning, search control, planning**.
- **Tabular Dyna-Q** is the canonical algorithm; the model is a deterministic table `Model(s, a) = (r, s')`.
- vs **Q-learning**, Dyna is more sample-efficient and generalizes better, but more complex and vulnerable to **model bias**.
- The hyperparameter **`n`** (planning steps per real step) trades compute for sample efficiency — `n = 0` is plain Q-learning.
- **Plan first, then play** — Dyna's planning updates are not a different algorithm; they are the same Q-learning rule applied to *simulated* transitions.
