# 2.2 Monte-Carlo for Control

## From State Values to Action Values

In the previous lecture we learned state values `V(s)` by averaging sample returns observed after visiting state `s`. For **control** (i.e., actually picking good actions) we need **action values** `Q(s,a)` — the expected return when we take action `a` in state `s` and then follow our policy thereafter.

The recipe is identical, just one level deeper:

- For `V(s)`: average returns `G_t` observed after visiting `s`.
- For `Q(s,a)`: average returns `G_t` observed after taking action `a` in state `s`.

### Why action values matter

Action values let us **compare actions inside the same state**. Once we have `Q(s,a)` for every available action, we can simply pick the action with the highest estimated value — that is the basis of a **greedy policy**.

> Analogy: Knowing a restaurant is good (`V`) is fine, but knowing which specific *dish* is best (`Q`) lets you actually order something great.

## The Exploration Problem

Suppose we only ever follow a **deterministic policy** π that picks one action per state. Then:

- We only ever observe returns for the actions π actually selects.
- Any **other action** that π never tries has **zero data** — we cannot form an accurate MC estimate of `Q(s,a)` for it.
- Worse, we have no way to discover that one of those untried actions might actually be better.

This is the **maintaining exploration** problem in RL. If we don't explore, we can't improve.

> Real-life joke: It's like only ever ordering the same dish at your favorite restaurant — you'll never know the new chef's special is twice as good for half the price.

> Slide example: You always walk home along your usual road. A new shortcut opens up, but unless you actually try it once, you'll never know it's faster.

## Exploring Starts

**Exploring Starts** is one way to force exploration in Monte-Carlo control.

- We guarantee that **every episode begins with a random state-action pair** `(S_0, A_0)`.
- After that first step, the agent follows its current policy π normally.
- By cycling through random starting pairs across many episodes, every `(s, a)` eventually gets visited and estimated.

This works beautifully in environments where we are free to reset the simulator to any initial configuration (e.g., Blackjack). It is **not** realistic in continuous, real-world control where you cannot teleport to arbitrary states.

## Generalized Policy Iteration (GPI) with Monte-Carlo

**GPI** is the conceptual backbone of nearly every RL control algorithm. It alternates two steps:

1. **Policy Evaluation** — estimate how good the current policy is.
2. **Policy Improvement** — update the policy to be greedy (or near-greedy) with respect to those estimates.

For MC control:

- **Policy Evaluation**: run episodes under the current policy and update `Q(s,a)` by averaging observed returns.
- **Policy Improvement**: set the new policy to be greedy w.r.t. `Q`:

```
π_{k+1}(s) = argmax_a Q(s, a)
```

Repeat. Each iteration produces a policy **at least as good** as the previous one. This is the same idea that drives value iteration, policy iteration, and later TD/SARSA — just with MC samples instead of a model.

## Blackjack Walkthrough

Blackjack is the canonical MC-control toy problem. Here is the agent's setup and one episode of learning.

### Setup

- Episodes begin in random states (random card deals) — a natural fit for **exploring starts**.
- We additionally pick a **random first action** (hit or stick) and then let the policy take over.
- Initial policy: **hit if sum < 20, stick otherwise.**

### Sample Episode

1. Agent starts with sum 13, no usable ace, dealer shows 8.
2. Random first action is **hit** → draws 7 → sum is now 20.
3. Policy now says **stick**. Dealer draws 9 and busts (>21). Agent gets reward **+1**.
4. Going backwards through the episode, the agent updates its return lists:
   - `Q(sum=20, stick) ← 1`
   - The hit at the start state was followed by the +1 reward, so `Q(sum=13, hit)` also gets +1 in its return list.
5. **Policy improvement** in the start state: the agent had never tried sticking (its value is 0), but hitting returned 1. The greedy action is therefore **hit**, and π updates to reflect that.

### Optimal Policy (after many episodes)

The agent eventually learns a near-optimal Blackjack policy with a couple of intuitive features:

- **With a usable ace**: the agent plays aggressively, often hitting until the sum is near 19. The flexible ace lets it safely absorb more cards.
- **Without a usable ace**: the policy depends heavily on the dealer's visible card. For example, the agent sticks at 13+ when the dealer shows a low card (2 or 3) because the dealer is likely to bust.

> Joke: MC control is like learning the best moves in a board game by playing thousands of rounds, writing down which openings worked, and gradually only choosing the ones that won.

## Why MC Control Works (and When It Doesn't)

**Strengths**

- **Model-free**: only needs sampled episodes, no knowledge of transition probabilities or rewards.
- **Unbiased**: averages of returns are unbiased estimates of the true `Q(s,a)`.
- **Simple**: no bootstrapping — we wait until the end of the episode to update.

**Weaknesses**

- **High variance**: returns depend on entire rollouts, which can be noisy.
- **Needs episodes to finish**: doesn't work in continuing (non-episodic) tasks without modifications.
- **Exploring starts assumption** is often unrealistic.

## Key Takeaways

- **MC control estimates `Q(s,a)`** by averaging returns observed after each state-action pair — same idea as MC for `V(s)`, just one level deeper.
- **Action values enable a greedy policy** by letting us compare actions inside each state.
- **Exploration is essential**: without it, we never observe returns for actions our deterministic policy never picks.
- **Exploring Starts** forces every episode to begin with a random `(s, a)`, guaranteeing coverage in environments where we control episode initialisation.
- **GPI + MC** = alternate *evaluate* (MC return-averaging) and *improve* (greedy w.r.t. `Q`); each loop yields a policy that is at least as good as the previous one.
- The Blackjack example shows the full MC-ES control loop in action — initial policy → sample episode → update `Q` → make policy greedy → repeat.
- Optimal policies found by MC control (e.g., Blackjack) match human intuition: aggressive with a usable ace, defensive without one and against weak dealer cards.
