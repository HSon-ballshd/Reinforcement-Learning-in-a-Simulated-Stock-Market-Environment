# 1.5 Goal of Reinforcement Learning

## What is Reinforcement Learning?

Reinforcement Learning (RL) is a **feedback-based learning paradigm** in which an agent interacts with an environment, takes actions, and improves its behavior through experience. Unlike supervised learning, there is **no labelled dataset** — the agent learns purely from trial-and-error signals it receives as consequences of its actions.

- The agent is **rewarded** for good actions and **punished** for bad ones.
- The **goal of the RL agent** is to **maximize the total (cumulative) reward** it collects over time.
- Analogy: a **child learning to walk** — every stumble is a "negative reward," every successful step a "positive reward." Over time, the child learns a policy that produces more standing, less falling.

## Two Categories of Reinforcement

- **Positive Reinforcement**: Adds something (a reward) to **increase the likelihood** that a behavior recurs. Example: giving a dog a treat when it sits on command.
- **Negative Reinforcement**: Removes something aversive to **increase the likelihood** of a behavior. Example: a car beeping stops when you fasten your seatbelt — the behavior (fastening) is reinforced.

> Note: "Negative reinforcement" is **not** punishment. It strengthens behavior by avoiding a negative condition.

## Key Components of an RL System

| Component | Role |
|---|---|
| **Agent** | The learner / decision-maker. |
| **Environment** | The external system the agent interacts with. |
| **State (S)** | A representation of the current situation; carries the info needed to decide. |
| **Action (A)** | The set of moves/choices the agent can take in a state. |
| **Reward (R)** | A scalar feedback signal after each (state, action) pair. |
| **Policy (π)** | The agent's strategy — a mapping from states to actions. |

These six pieces — agent, environment, state, action, reward, policy — are the backbone of every RL formulation.

## Supervised Learning vs. Reinforcement Learning

| Aspect | Supervised Learning | Reinforcement Learning |
|---|---|---|
| **Objective** | Learn a mapping from inputs to output **labels**. | Learn a **policy** that maximizes **cumulative reward**. |
| **Training Data** | Labeled (input, output) pairs. | Reward feedback from interaction — **no labels**, learns by trial and error. |
| **Feedback Signal** | Ground-truth labels; minimize prediction error. | Scalar rewards indicating the *desirability* of actions. |
| **Use Case** | Classification, regression, object detection. | Sequential decision-making: robotics, games, autonomous driving, resource management. |
| **Examples** | Image classification, spam detection, sentiment analysis. | Playing chess/Go, robotic control, self-driving cars. |

**Key contrast**: supervised learning is told the right answer; RL is only told *how good* the answer was, and must discover the right answer by experimenting.

## Formal Goal of the RL Agent

The agent must choose a policy π that maximizes the **expected return** $G_t$, defined as the sum of future rewards from time $t$ onward. Conceptually:

```
G_t = R_{t+1} + R_{t+2} + R_{t+3} + ... + R_T
```

The agent's objective is therefore:

```
max_π  E[G_t | π]
```

In other words: **select actions so that, in expectation, the total future reward is as large as possible.** The *cumulative* nature of the objective is what makes RL different from one-step prediction — sacrificing a small reward now may yield a much larger one later.

> Analogy: A chess player doesn't greedily capture the next piece — they sacrifice material to set up a checkmate ten moves later. That's exactly the kind of **long-horizon, delayed-reward reasoning** RL tries to capture.

## Episodic Tasks

An **episodic task** is one in which the agent's experience is broken into discrete **episodes**. Each episode:

- starts from an **initial state**,
- proceeds through a sequence of state-action-reward transitions,
- ends at a **terminal state**,
- then **resets** and a new episode begins.

### Characteristics of Episodic Tasks

- **Episode termination**: ends after a finite number of steps or when a goal/terminal condition is met.
- **Finite horizon**: a bounded number of time steps per episode (length may vary episode-to-episode).
- **Goal-oriented**: the agent typically aims to reach a particular state (e.g., winning the game, reaching the goal cell of a maze).

### Examples of Episodic Tasks

- A **single game of chess** (terminal state = checkmate or draw).
- **Solving a maze** (terminal state = exit reached).
- **Robotic navigation** to a target location.
- **Solving a puzzle** within a fixed number of moves.

### Episodic vs. Continuing Tasks

- **Episodic**: finite, clearly bounded episodes (chess match, Atari game round).
- **Continuing**: no natural terminal state; the agent-environment interaction goes on indefinitely (a process controller, a stock-trading bot running 24/7). For continuing tasks, return is often written as a discounted sum $G_t = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}$ with $0 \le \gamma < 1$ to keep it finite.

## Key Takeaways

- **RL is feedback-driven learning**: an agent learns from rewards and punishments, not from labelled examples.
- The **single formal goal** of RL is to learn a policy π that **maximizes the expected cumulative reward** $E[G_t]$.
- Six core components define every RL problem: **agent, environment, state, action, reward, policy**.
- RL differs from supervised learning chiefly in its **delayed, scalar reward signal** and its focus on **sequential decisions** rather than one-shot predictions.
- **Positive vs. negative reinforcement** both strengthen behavior — only the mechanism (adding reward vs. removing aversive stimulus) differs.
- **Episodic tasks** terminate at an end state and reset, allowing the agent to repeatedly practice reaching a goal.
- A good policy trades off **immediate vs. long-term reward**, exactly like a chess player planning a checkmate rather than grabbing the next piece.
