# Generalized Policy Iteration (GPI)

## What is GPI?

**Generalized Policy Iteration (GPI)** is the unifying framework behind nearly every RL algorithm that computes value functions and policies. Instead of treating policy evaluation and policy improvement as two separate, sequential procedures, GPI says: keep both processes running, and let them pull each other toward the optimum.

> **Analogy — two teams pulling a rope.** Team A pulls one end toward the "true value," and Team B pulls the other end toward the "greedy policy." Neither team ever reaches the finish line on its own, but together they tighten the rope until both ends meet at the optimal joint solution.

Formally, GPI alternates between two interacting processes:

1. **Policy Evaluation** — estimate the value function `v_π` (or `q_π`) of the *current* policy.
2. **Policy Improvement** — make the policy *greedy* with respect to the current value function so that it does at least as well as before.

```
Evaluation:   π  →  v_π
Improvement:  v_π  →  π' = greedy(v_π)
```

The loop `evaluation → improvement → evaluation → …` is the engine of policy iteration, value iteration, and (in disguise) Q-learning, SARSA, and TD(λ).

---

## The Two Processes in Detail

### Policy Evaluation

Given a policy `π`, compute how good it is from every state:

```
v_π(s) = Σ_a π(a|s) Σ_{s',r} p(s',r|s,a)[ r + γ v_π(s') ]
```

This is a system of linear equations. In practice we *iterate* the Bellman expectation backup until `v` is close enough to `v_π`.

### Policy Improvement

Once we have `v_π`, we can do a *greedy* one-step lookahead:

```
π'(s) = argmax_a  Σ_{s',r} p(s',r|s,a)[ r + γ v_π(s') ]
```

By the **Policy Improvement Theorem**, `v_{π'}(s) ≥ v_π(s)` for every state `s`, with strict inequality somewhere unless `π` is already optimal. That guarantee is what makes the iteration monotonically improve.

> **Joke break.** Why did the value function cross the Bellman equation? To get to the other *side* of greedy.

---

## Policy Iteration vs. Value Iteration (a GPI Spectrum)

The key insight is that GPI is a *spectrum*. Policy iteration runs evaluation **to completion** before improving; value iteration runs evaluation for only **one sweep** before improving.

```
Policy iteration:   many sweeps of evaluation → 1 improvement → repeat
Value iteration:    1 sweep of evaluation   → 1 improvement → repeat
```

### Value Iteration as a GPI Special Case

Value iteration collapses policy evaluation to a single Bellman *optimality* backup:

```
v_{k+1}(s) = max_a Σ_{s',r} p(s',r|s,a)[ r + γ v_k(s') ]
```

This is still GPI: the "policy" is implicit — it is just `greedy(v_k)` at every step. Each iteration does one sweep over all states, then re-greedifies. Because the Bellman optimality operator `T*` is a **γ-contraction** in max-norm,

```
||T*u − T*v||_∞  ≤  γ ||u − v||_∞,   0 ≤ γ < 1
```

repeated application converges to the unique fixed point `v*` at a geometric rate `γ^k`.

The same contraction argument applies to policy evaluation (`T_π` is also a `γ`-contraction) — that's why iterative policy evaluation is guaranteed to converge.

## Synchronous vs. Asynchronous Dynamic Programming

Both policy iteration and value iteration can be run in two flavors.

### Synchronous DP

- All state values are updated **simultaneously** at each iteration, using only values from the previous sweep.
- Storage: two copies of the value array (`v_old` → `v_new`).
- **Pro:** simple, parallelizable, easy to reason about (each sweep is one application of an operator).
- **Con:** a full sweep may be infeasible when the state space is huge or continuous.

```
For k = 0, 1, 2, …:
  for each s in S (in parallel):
      v_new(s) = max_a Σ p(s',r|s,a)[ r + γ v_old(s') ]
  v_old ← v_new
```

### Asynchronous DP

- States are updated **one at a time**, in arbitrary order, using the *latest* values available.
- No separate `v_old` / `v_new` arrays needed — you overwrite in place.
- **Pro:** scales to large state spaces; lets you prioritize "important" states.
- **Con:** convergence depends on the update schedule visiting every state infinitely often.

Common strategies:

- **Prioritized sweeping** — update states whose Bellman error is largest first.
- **Real-time DP / online TD(λ)** — only update states actually visited by the agent.
- **In-place Q-learning** — sample-by-sample stochastic updates.

As long as every state is visited infinitely often and step sizes satisfy Robbins–Monro conditions, asynchronous DP converges to the same `v*` as the synchronous version. The contraction property still holds because each individual backup is still a `γ`-contraction step.

## Why GPI Works — The Intuition

Two forces pull `v` and `π` toward each other:

- Evaluation makes `v` track the **current** policy exactly.
- Improvement makes `π` greedy with respect to the **current** `v`, which means `π` is "trying" to track `v`.

Neither process waits for the other to finish. As long as they keep nudging each other, the pair `(v, π)` converges to `(v*, π*)`. This is why almost every RL method — tabular or deep — can be seen as an instance of GPI:

| Algorithm | Evaluation step | Improvement step |
|---|---|---|
| Policy Iteration | full sweep until convergence | full greedy update |
| Value Iteration | one Bellman-optimality sweep | implicit greedy |
| Q-Learning | one-sample TD update on `q` | implicit greedy over `q` |
| Actor-Critic | critic fits `v_π` or `q_π` | actor updates `θ` via policy gradient |

> **Example — learning to drive.** Evaluation is "look at the route you took and judge how smooth it was." Improvement is "next time, steer a little more like the smooth parts." You don't wait until your self-assessment is perfect before adjusting the wheel — you keep doing both, and gradually the driving (policy) and the self-rating (value) get better together.

---

## Key Takeaways

- **GPI** unifies all RL algorithms that juggle a value function and a policy: alternate *evaluation* (compute `v_π`) and *improvement* (act greedily w.r.t. `v`).
- **Policy iteration** runs evaluation to completion; **value iteration** runs only one sweep per iteration — both are GPI, just at different points on the spectrum.
- **Value iteration converges** because the Bellman optimality operator `T*` is a `γ`-contraction in max-norm, guaranteeing a unique fixed point `v*` at rate `O(γ^k)`.
- **Synchronous DP** updates all states at once using a previous-sweep snapshot; **asynchronous DP** updates states one-by-one in place and scales to large or continuous problems.
- Asynchronous methods (prioritized sweeping, TD(λ), online Q-learning) still converge provided every state is visited infinitely often and learning rates meet Robbins–Monro conditions.
- Almost every practical RL algorithm — from tabular Q-learning to deep actor-critic — is an instance of GPI with some specific choice of evaluation and improvement step.
