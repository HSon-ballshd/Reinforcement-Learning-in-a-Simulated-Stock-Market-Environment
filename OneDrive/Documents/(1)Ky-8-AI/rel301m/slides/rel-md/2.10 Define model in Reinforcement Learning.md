# 2.10 Defining a Model in Reinforcement Learning

## What is a Model?

In RL, a **model** is the agent's internal representation of how the environment behaves. Given a current state and action, the model tells the agent what *might* happen next — both the next state and the reward — without the agent having to actually take that step in the real world.

Think of it as a **"simulation of the world"** that lives inside the agent. A weather forecast app is a great analogy: it does not actually create weather, but it predicts what tomorrow's weather (and your resulting picnic) will look like based on what it knows today.

Mathematically, a model captures the **dynamics** of the environment. The most general form is the four-argument probability function:

```
P(s', r | s, a)
```

which gives the probability of landing in next state `s'` and receiving reward `r` when the agent is currently in state `s` and takes action `a`.

A model is useful because it enables **planning** — using the model to simulate experience and improve a policy *without* additional real-world interaction.

## Why Models Matter: Planning and Sample Efficiency

Models are not just descriptive; they are used for **planning**: the process of using a model to improve a policy.

One common planning approach:

1. Use the model to **simulate** transitions `(s, a, s', r)`.
2. Perform **value-function updates** on those simulated transitions as if they had actually happened.
3. The improved value estimates guide better decisions.

The big payoff is **sample efficiency**. By mixing real and simulated experience, the agent needs *fewer interactions with the real environment* to reach the same level of policy quality. This is exactly how training a self-driving car works — you cannot crash real cars a million times, so you train on a simulator first.

## Two Types of Models

There are two fundamentally different ways to encode the dynamics `P(s', r | s, a)`.

### Sample Models

A **sample model** produces a single concrete outcome drawn from the underlying probabilities.

- Instead of telling you "the probability of heads is 0.5", a coin-flip sample model just spits out **a random sequence** of heads and tails.
- In a gridworld, given `(s, a)`, it directly returns *one* specific next state and reward sampled from the transition dynamics.

Implementation-wise, sample models follow simple rules: e.g., "flip five coins = independently pick 0 or 1 five times." Each flip only needs to produce a single outcome.

**Pros**
- Computationally inexpensive.
- Easy to implement — just generate random outcomes from a set of rules.

**Cons**
- Do **not** explicitly capture uncertainty.
- Can be memory-heavy if you need to store many samples.
- Less informative per query (you only see one outcome, not the full picture).

### Distribution Models

A **distribution model** specifies the full probability of *every* possible outcome.

- For the coin: it says "heads 50%, tails 50%" — and can also work out the odds of any sequence of flips.
- For a gridworld `(s, a)`: it returns the probability of moving to each neighbor and the probability of receiving each possible reward.

**Pros**
- Captures **uncertainty** explicitly.
- Richer information per query.
- Better suited for stochastic environments where you must reason about variance.

**Cons**
- **Hard to specify** and can become very large.
- For five coin flips, a distribution model would have to enumerate **all 32 possible sequences** and assign a probability to each one. Even for a trivial problem, the representation blows up combinatorially.

## Side-by-Side Comparison

| Aspect | Sample Model | Distribution Model |
|---|---|---|
| **Output** | A single `(s', r)` drawn from the dynamics | Full probability distribution over all `(s', r)` |
| **Captures uncertainty?** | Implicitly (via repeated sampling) | Explicitly (as a distribution) |
| **Compute cost** | Cheap per query | Can be expensive per query |
| **Memory** | Small (just rules to sample from) | Can grow combinatorially |
| **Best for** | Deterministic envs or when samples are easy | Stochastic envs or when uncertainty must be reasoned about |

## Choosing Between Them

Use a **distribution model** when:

- The environment is stochastic and you need to reason about the full spread of outcomes.
- You need a measure of uncertainty (e.g., risk-sensitive decisions).
- You want to integrate analytically over outcomes.

Use a **sample model** when:

- The environment is mostly deterministic.
- You only need a single plausible next step.
- Storage and compute are tight (think: high-dimensional robotics where enumerating all states is impossible).

In modern model-based RL (e.g., AlphaZero-style systems, MuZero, world models for robotics), **sample models** dominate because real environments have astronomical state spaces — you simply cannot store a full distribution.

## Concrete Examples from the Lecture

- **Sample model — coin flips**: Independently pick H/T five times to generate a sequence like `H, T, H, H, T`. Only one outcome produced per flip.
- **Distribution model — coin flips**: Enumerate all 32 possible 5-flip sequences, each with probability `(1/2)^5 = 1/32`.
- **Distribution model — two-armed bandit**: Store the probability distribution over rewards for each arm and update it as pulls are observed.
- **Sample model — gridworld**: From state `s` taking action "right", return one specific `(s', r)` drawn from the environment's transition probabilities.

## Key Takeaways

- A **model** is the agent's internal representation of environment dynamics, formally `P(s', r | s, a)`.
- Models enable **planning** — simulating experience to improve a policy without additional real-world interaction, boosting **sample efficiency**.
- A **sample model** returns one concrete `(s', r)` outcome drawn from the dynamics — cheap and simple, but ignores explicit uncertainty.
- A **distribution model** returns the full probability distribution over all `(s', r)` — captures uncertainty but can be combinatorially large.
- Choose a **distribution model** when you need explicit uncertainty or stochastic reasoning; choose a **sample model** when environments are deterministic or when enumerating states is infeasible.
- Modern large-scale model-based RL almost always uses **sample models** because real environments are too big to represent distributionally.
- Combining real experience with **simulated experience** from a model is the central trick that makes model-based RL dramatically more sample-efficient than model-free RL.
