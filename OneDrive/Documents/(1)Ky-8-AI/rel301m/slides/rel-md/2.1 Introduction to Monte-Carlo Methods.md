# 2.1 Introduction to Monte-Carlo Methods

## What Are Monte-Carlo Methods?

**Monte-Carlo (MC) methods** are a class of computational algorithms that rely on **random sampling** to obtain numerical results. In reinforcement learning, they are used to estimate value functions or policies by **sampling trajectories (episodes)** of interaction between an agent and its environment.

The core idea is brutally simple: instead of computing a value exactly from a known model, we **average over a large number of random samples** to approximate it.

> **Analogy — "learn by doing":** Imagine you want to know the average sum of 12 dice rolls. The true expected sum is `12 × 3.5 = 42`. Roll 12 dice a few times and you might get 41.57 — close, but not exact. Roll them many more times and your average creeps toward 42. That's Monte-Carlo in one sentence.

---

## Why MC Works: The Law of Large Numbers

The mathematical guarantee behind MC is the **Law of Large Numbers**:

- As the number of samples grows, the sample average converges to the true expected value.
- The more returns the agent observes from a state, the more likely the sample average is close to that state's true value.

In RL terms: collect enough episodes and your estimate `V(s)` will get arbitrarily close to the true `v_π(s)`.

---

## MC in RL: Estimating Value Functions

### From Bandits to Full RL

In a **multi-armed bandit**, you estimate the value of an arm by averaging the payoffs you got from pulling it.

MC for RL generalizes this: instead of estimating the value of an **arm**, we estimate the value of a **state under a policy** by averaging the returns obtained when following that policy from that state until the episode terminates.

### MC Prediction Formula

The canonical MC prediction estimate is:

```
V(s) = average of returns observed following visits to s
```

Where a **return** `G_t` from time `t` is the cumulative discounted reward:

```
G_t = R_{t+1} + γ R_{t+2} + γ² R_{t+3} + ... + γ^(T-t-1) R_T
```

`T` is the terminal time step of the episode.

### Two Variants: First-Visit vs Every-Visit MC

- **First-visit MC:** average the returns following the **first** visit to state `s` in each episode.
- **Every-visit MC:** average the returns following **every** visit to `s` within each episode.

Both converge to `v_π(s)` as the number of visits grows, but they have slightly different bias/variance properties. **First-visit** is the classic, textbook formulation.

### Key Restriction: Episodic Tasks Only

Returns can only be observed at the **end of an episode**, so MC methods (as introduced in this lecture) are restricted to **episodic tasks** — those with a terminal state. Continuing tasks require extensions (e.g., TD learning, covered later).

## Worked Example: Computing Returns by Hand

Suppose `γ = 0.05` and an episode at `t = 0..5` produces the reward sequence `R_1=3, R_2=4, R_3=7, R_4=1, R_5=2`. Compute each return `G_t` backwards:

```
G_5 = 2
G_4 = R_5 + γ·G_5        = 2 + 0.05·2         = 2.10
G_3 = R_4 + γ·G_4        = 1 + 0.05·2.10      = 1.105
G_2 = R_3 + γ·G_3        = 7 + 0.05·1.105     = 7.05525
G_1 = R_2 + γ·G_2        = 4 + 0.05·7.05525   = 4.3527625
G_0 = R_1 + γ·G_1        = 3 + 0.05·4.3527625 = 3.217638...
```

**Trick:** Each return shares the term `γ^(k) · R_{t+k}` with the next. The deepest return (`G_5`) is trivial — it's just the last reward. Computing backwards is fast because you re-use the partial sum.

## The Blackjack Example

Blackjack is the **canonical MC example** in Sutton & Barto — and it shows up in the slides too.

### Game Setup
- Agent plays against a dealer.
- States are described by: the agent's current sum (12–21), the dealer's visible card (ace–10), and whether the agent holds a **usable ace**.
- **Actions:** `hit` (draw another card) or `stick` (end your turn).
- **Reward:** `+1` for a win, `−1` for a loss, `0` for a draw, awarded at the end of the episode.

### Walkthrough (policy is "hit until ≥ 20, else hit")
1. State A: agent has 13, no usable ace; dealer shows 10. Policy says hit → draws 7 → sum is 20 → sticks.
2. Dealer draws 9 → busts → agent wins → reward `+1`.
3. State B: same view as A (13, no usable ace, dealer shows 10). Policy again hits → draws 7 → 20 → sticks → dealer busts → agent wins → reward `+1`.

### Updating the Value Estimate
- After state A's episode: append `+1` to the **returns list for state A**. Set `V(A) = average(list_A)`.
- After state B's episode: append `+1` to the **returns list for state B**. Set `V(B) = average(list_B)`.

Over many simulated episodes, `V(A)` and `V(B)` stabilize near their true values. Notice that states A and B look identical to the agent (same player sum, same dealer up-card, same ace status) — so they will share the **same** returns list. This is the central challenge: how do you distinguish them? In standard Blackjack MC, you don't — they're the same state.

## When MC Methods Are Useful

MC prediction shines when:
- You **don't have a model** of the environment (transitions/rewards unknown).
- You can **simulate episodes** cheaply (or replay logged trajectories).
- The task is **episodic** with a clear terminal state.

MC is also the conceptual bridge between **bandit-style averaging** and full RL — once you accept that "average samples = expected value," the entire MC family falls out naturally.

---

## Key Takeaways

- **MC methods estimate values by averaging sample returns** from many simulated episodes — grounded in the Law of Large Numbers.
- They require only **sample experience** (or a simulator), not a model of the environment.
- The core MC prediction formula: `V(s) = average of returns following visits to s`.
- **First-visit MC** uses only the first visit per episode; **every-visit MC** uses every visit — both converge to `v_π(s)`.
- Returns are computed **backwards** from the terminal reward using `G_t = R_{t+1} + γ G_{t+1}`.
- MC methods (as introduced here) are limited to **episodic tasks** because returns are only known at episode end.
- **Blackjack** is the canonical worked example: states = (player sum, dealer up-card, usable ace), rewards = `+1 / 0 / −1`, value estimates built by averaging observed returns per state.
