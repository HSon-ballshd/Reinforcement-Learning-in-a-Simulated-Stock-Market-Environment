# 3.2 The Objective for On-policy Prediction

## Overview

This lecture zooms in on **policy evaluation with function approximation**: how do we measure how good our value estimate is, and how do we tweak the weights `w` to make it better? The three pillars are the **MSVE objective**, **stochastic gradient descent**, and **state aggregation** as a concrete form of linear value-function approximation.

---

## 1. The Value Error Objective

### 1.1 Why We Need an Objective

When we approximate `Vπ(s)` with a parameterized function `V̂(s, w)`, the approximation is rarely perfect. We need a **scalar score** that says "how wrong are we, on average?" so we can drive `w` in the right direction.

> Real-life analogy: a self-driving car's lane-keeping model isn't perfect. You measure its error by how far the predicted trajectory is from the actual one — averaging over many trips, weighted by how often you encounter each road type.

### 1.2 Mean Squared Value Error (MSVE)

```
MSVE(w) = Σ_s d_π(s) · [v_π(s) − V̂(s, w)]²
```

- `v_π(s)` — the **true value** of state `s` under policy `π`.
- `V̂(s, w)` — our **approximate value**, parameterized by weights `w`.
- `d_π(s)` — the **on-policy distribution**: how often we expect to visit state `s` while following `π`. States we actually live in get more weight; rare states get less.
- The square penalizes large errors disproportionately, and the sum (or expectation) averages over the state space.

> Joke to remember it: "Give more weight to where you spend your time." If you only ever commute between home and work, your driving-skill score shouldn't weight icy mountain passes as heavily as the highway.

> We call this objective `VĒ` (V-bar / VE-bar): the bar denotes an average over states, weighted by `d_π`.

### 1.3 Why On-policy Weighting Matters

If we weighted errors **uniformly** across all states, we'd waste effort accurately predicting states we'd never visit. By weighting with `d_π`, we focus the approximator's capacity on the **states the agent will actually see under its current policy** — exactly what we care about for on-policy prediction.

## 2. Gradient Descent in RL

### 2.1 The Big Idea

**Gradient descent** is the workhorse optimizer: move `w` in the direction that locally *decreases* the objective.

```
w_{t+1} = w_t − α · ∇J(w_t)
```

where `α` is the learning rate (step size) and `∇J(w)` is the gradient of the objective with respect to the weights.

The slides identify three families of RL methods where gradient descent shows up:

| Family | What we approximate | Loss we minimize |
|---|---|---|
| **Policy gradient** | `π_θ(a\|s)` directly | Negative expected return |
| **Value-function approximation** | `V̂(s, w)` or `Q̂(s, a, w)` | MSVE or TD error |
| **Actor-Critic** | Both policy (actor) and value (critic) | Combination of the two |

### 2.2 Why Gradient Descent Fits RL

- **Policy gradient methods** learn a parameterized policy `π_θ(a|s)` and apply the **policy gradient theorem** to compute `∇θ E[Return]`, then nudge `θ` to favor high-return actions.
- **Value-based methods** learn `V̂(s, w)` or `Q̂(s, a, w)` and minimize the **MSVE** (or TD error).
- **Off-policy** value methods (e.g. Q-learning) can still use gradient descent on the TD error — the experience distribution differs from the target, but the gradient computation is the same.
- **Actor-Critic** updates both: actor via policy gradient, critic via value-based TD.

> Analogy: gradient descent is like hiking downhill in fog. You can only see your local slope, so you take small steps downhill and hope you don't end up in a puddle (local minimum) instead of the lake (global minimum).

### 2.3 Local vs Global Optima

The lecture reminds us that gradient descent finds **local minima**, not always the global one. In RL this is usually fine — the objective surface is complex and a "good enough" value function is far better than none.

## 3. Gradient for Policy Evaluation

### 3.1 The Stochastic Gradient

Since `MSVE(w)` is a sum over states weighted by `d_π`, its gradient is:

```
∇MSVE(w) = E_{s ~ d_π} [ 2 · (V̂(s, w) − v_π(s)) · ∇_w V̂(s, w) ]
```

Dropping the constant `2` (it just gets absorbed into the learning rate), the **update direction** becomes:

```
w ← w − α · (V̂(s, w) − v_π(s)) · ∇_w V̂(s, w)
```

This is the **stochastic gradient descent** form: at each step we sample a single state `s`, compute the prediction error `(V̂(s,w) − v_π(s))`, and nudge `w` opposite to the gradient scaled by that error.

> Real-life analogy: rating a movie. If your predicted rating is 3 stars but the actual is 5, your prediction model was too pessimistic. The gradient tells you **which feature weights to nudge up** (e.g. acting, soundtrack) and by how much.

### 3.2 Reading the Sign of the Error

The slides emphasize the intuition behind the sign:

- **Error is positive** (`V̂(s,w) < v_π(s)`): true value higher than estimate → update weights **up** the gradient direction to **increase** `V̂`.
- **Error is negative** (`V̂(s,w) > v_π(s)`): true value lower than estimate → update weights **down** to **decrease** `V̂`.

So the gradient literally tells you "which direction to push the weights so this state's predicted value moves toward the truth."

## 4. State Aggregation

### 4.1 What It Is

**State aggregation** groups similar states and shares a single value across the whole group. With `k` groups we only need `k` weights, regardless of how many underlying states there are.

> Real-life analogy: a thermostat doesn't model the temperature of every cubic millimeter of air in your house — it tracks "room temperature" as one number. You're aggregating millions of micro-states into a single feature.

### 4.2 Linear Function Approximation in Disguise

State aggregation is actually a special case of **linear function approximation**:

- Each group `g` gets a **feature** `x_g(s)`:

```
x_g(s) = 1  if s ∈ group g
x_g(s) = 0  otherwise
```

- The approximate value is the group's weight:

```
V̂(s, w) = Σ_g x_g(s) · w_g = w_{g(s)}
```

### 4.3 Concrete Example (from the slides)

Imagine **8 states** in a table. Aggregate them into **2 groups of 4**:

- Group A: states `{s1, s2, s3, s4}` → weight `w_A`
- Group B: states `{s5, s6, s7, s8}` → weight `w_B`

Updating `V̂(s1, w)` automatically updates the value of `s2, s3, s4` too. This **generalization** is the key win — you learn faster because each update informs multiple states.

### 4.4 Why It Matters

- **Computational tractability**: 8 states → 2 weights.
- **Generalization**: similar states share information, improving sample efficiency.
- **Foundation**: state aggregation is the simplest stepping stone to richer feature-based linear (and later non-linear) function approximation.

---

## Key Takeaways

- **MSVE** is the canonical objective for on-policy prediction: a state-weighted average of squared errors between true and approximate values.
- The **on-policy distribution `d_π(s)`** decides which states matter most — weight error by how often you visit each state.
- **Gradient descent** updates weights as `w ← w − α · ∇J(w)`; in RL it powers policy gradients, value-function fitting, actor-critic, and even off-policy TD methods.
- The **value-error gradient** is proportional to `(V̂(s,w) − v_π(s)) · ∇V̂(s,w)` — a positive error pushes weights toward raising the prediction, a negative one lowers it.
- **State aggregation** groups states and shares a weight per group, dramatically reducing the number of parameters.
- Aggregation is a form of **linear function approximation** with one-hot group-membership features.
- The whole pipeline — define `MSVE`, descend its gradient, choose a feature representation like aggregation — is the template for almost every value-function approximator you'll see later in the course.
