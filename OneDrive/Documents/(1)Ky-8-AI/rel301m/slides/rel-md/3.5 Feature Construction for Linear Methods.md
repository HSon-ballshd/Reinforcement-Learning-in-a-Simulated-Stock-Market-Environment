# Feature Construction for Linear Methods

## Why Feature Construction Matters

In linear function approximation, we estimate a value (or Q-value) as a **linear combination of features**:

```
v̂(s, w) = w^T x(s) = Σ_i w_i · x_i(s)
```

The feature vector `x(s)` is the agent's way of *describing* a state. The richer and better-shaped the features, the easier learning becomes. This lecture covers three practical recipes for building `x(s)`: **coarse coding**, **tile coding**, and the conceptual balance between **discrimination** and **generalization**.

### Real-life analogy
Think of features as different ways to describe where you are. "I am on the 3rd floor" (coarse), "I am in room 3.14" (fine), "I am within 1 meter of the coffee machine" (radial). Each description gives the agent a different lens on the same reality.

---

## Coarse Coding

**Coarse coding** is a generalization of *state aggregation*. In state aggregation, the state space is partitioned into disjoint regions and each region activates exactly one feature. In coarse coding, the regions (called **receptive fields**) are allowed to **overlap**.

- A state `s` activates a feature if `s` lies inside that feature's receptive field.
- The feature vector is a binary (0/1) vector where each entry corresponds to one receptive field (e.g., one circle in the classic "fish in a pond" diagram).

```
x(s) = [x_1(s), x_2(s), ..., x_n(s)],   x_i(s) ∈ {0, 1}
```

### Properties
- **High-dimensional representation**: even though a state only activates a few features, the *vector* can have many components.
- **Local generalization**: nearby states activate an overlapping set of features, so they receive similar value estimates.
- **Flexibility**: by changing the *shape, size, and density* of receptive fields, you tune how much the agent generalizes.

### State aggregation vs. coarse coding
- State aggregation → non-overlapping cells → exactly **one** feature active per state.
- Coarse coding → overlapping receptive fields → **multiple** features can be active simultaneously.

> Imagine dropping a handful of fuzzy circles (the receptive fields) onto a giant map. A state's coordinates "light up" whichever circles contain it. Move slightly and the lights shift gradually, not abruptly.

---

## Discrimination vs. Generalization

These two forces pull learning accuracy in opposite directions, and feature construction is essentially the art of balancing them.

### Discrimination
The ability to **distinguish** between different states or classes.
- Strong discrimination = fine-grained features, narrow receptive fields.
- Risk: **overfitting** — the model memorizes noise or irrelevant details and fails on unseen states.

### Generalization
The ability to **transfer** knowledge to unseen but similar states.
- Strong generalization = broad receptive fields, many overlapping features.
- Risk: **underfitting** — the model is too coarse to capture important patterns.

### The trade-off
| More discrimination | More generalization |
|---|---|
| Narrow receptive fields | Wide receptive fields |
| Many active features per state | Few, broad features |
| Risk of overfitting | Risk of underfitting |

The goal of feature construction is to **choose receptive-field shape, size, and overlap** so that similar states share enough features to generalize, while distinct states differ in at least a few active features to be discriminated.

> A joke: a perfectly discriminative agent treats "room 3.14" and "room 3.15" as completely different worlds. A perfectly generalizing agent thinks every room is just "a room with a door." You want to be somewhere in the middle.

## Tile Coding

**Tile coding** is the workhorse form of coarse coding in practice. Think of it as laying a **checkerboard overlay** on top of the state space — except you stack several offset grids.

### How it works
1. **Partition** the continuous state space into a grid of **tiles** (hyper-rectangles in high dimensions).
2. Stack **multiple tilings**, each offset by a fraction of a tile width, so the tiles of one tiling interleave with those of another.
3. For a state `s`, the feature vector has exactly **one active feature per tiling** (the tile `s` falls into). So with `T` tilings, exactly `T` features are 1 and the rest are 0.

```
x_i(s) = 1  iff  s lies in tile i of some tiling
```

### Why it's popular
- **Efficient**: lookup is `O(T)` per state — just find the one tile per tiling.
- **Sparse features**: only a handful of the `x_i(s)` are nonzero, which speeds learning.
- **Tunable resolution**: increase the **number of tilings** for finer discrimination; widen the **tiles** for stronger generalization.

### Tile coding in TD learning
The tile-coded feature vector `x(s)` plugs straight into the linear approximator:

```
v̂(s, w) = w^T x(s)
Q̂(s, a, w) = w^T x(s, a)
```

Updates (e.g., semi-gradient TD(0)) then become:

```
w ← w + α · [R + γ · v̂(s', w) − v̂(s, w)] · x(s)
```

Because `x(s)` is sparse, each update only touches a small number of weights — fast and stable even in high-dimensional spaces.

> Analogy: imagine you are lost in a city. Each "tiling" is a different colored grid of squares painted on the streets. A red grid might put you in square R-7-3, a blue grid in B-2-8, a green grid in G-5-1. Your full "address" — `x(s)` — is the triple `(R-7-3, B-2-8, G-5-1)`. The offset between grids means even neighboring intersections get different triples, so you can still tell them apart.

## Practical Notes for Choosing Features

- **Number of tilings `T`** controls the smoothness of generalization. More tilings → finer discrimination.
- **Tile width** controls locality. Smaller tiles → more discrimination, less generalization.
- **Receptive field shape**: in low dimensions use squares/tiles; in higher dimensions use **radial basis functions** (Gaussian "fuzzy circles" around anchor points) to avoid the curse of dimensionality.
- **Hashing**: when the state space is huge, use hash tables to map tile indices to a fixed-size feature vector, keeping memory bounded.

---

## Key Takeaways

- **Coarse coding** generalizes state aggregation by allowing overlapping receptive fields, so multiple features can fire per state.
- The feature vector `x(s)` is binary (0/1) in coarse coding, with each entry tied to one receptive field.
- **Discrimination** and **generalization** are opposing forces — overdoing either causes overfitting or underfitting — and feature shape/size/overlap is how you tune the balance.
- **Tile coding** is the practical, fast form of coarse coding: stack offset grids so each tiling contributes one active feature, giving a sparse `x(s)` with `T` ones.
- Tile coding is `O(T)` per lookup and pairs naturally with linear semi-gradient TD/Q-learning.
- Increasing the **number of tilings** or shrinking **tile width** boosts discrimination; widening tiles boosts generalization.
- In higher-dimensional spaces, prefer **radial basis functions** or hashed tile coding to avoid exponential blow-up.
