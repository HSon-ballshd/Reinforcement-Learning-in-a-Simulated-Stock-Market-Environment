# 1.7 Policies and Value Functions

This lecture introduces two of the most fundamental objects in Reinforcement Learning: **policies** (what the agent *does*) and **value functions** (how the agent *judges* what to do). Together, they are the building blocks of almost every RL algorithm you'll meet later in the course.

## Policies

A **policy** is the agent's strategy — it maps states of the environment to actions the agent should take. It fully determines the agent's behavior.

Think of a policy as a **playbook** or recipe book: in every situation (state), it tells the player (agent) exactly which move (action) to make.

### Deterministic Policy

A **deterministic policy** picks exactly one action for every state with certainty:

```
π(s) = a
```

No randomness, no coin flips — given the same state, the agent always takes the same action.

**Example:** On a grid where the agent must walk home, each cell (state) has a single arrow pointing in the direction the agent moves. Each arrow = one deterministic choice.

### Stochastic Policy

A **stochastic policy** returns a probability distribution over actions for each state:

```
π(a|s) = P(A = a | S = s)
```

For every state, this distribution must satisfy:

- All action probabilities are **non-negative**: `π(a|s) ≥ 0`
- They **sum to one** across all actions: `Σ_a π(a|s) = 1`

**Example:** In the same grid-world, the bottom row might pick "up" or "right" each with probability 0.5. The agent still reaches home, but the path is random each episode.

### Why two types?

Deterministic policies are simple but rigid. Stochastic policies are essential when:

- The environment is partially observable or adversarial (e.g., rock–paper–scissors — a fixed policy always loses).
- You need to explore during learning.
- The optimal strategy is genuinely mixed (as in many two-player games).

## Value Functions

The **value function** estimates the *long-term* expected return an agent will receive starting from a given state (or state–action pair) and then following some policy π. It is how the agent answers: *"How good is being here? How good is doing this?"*

Think of the value as the **expected future winnings** in a game you're currently playing — not the points in your hand right now, but everything you'll probably earn from here on out if you keep playing by the rules.

### State-Value Function `v_π(s)`

The **state-value function** is the expected return when starting in state `s` and thereafter following policy `π`:

```
v_π(s) = E_π[ G_t | S_t = s ]
       = E_π[ Σ_{k=0}^∞ γ^k · R_{t+k+1} | S_t = s ]
```

Where:
- `G_t` is the **return** (cumulative discounted reward) from time `t`.
- `γ ∈ [0, 1]` is the **discount factor** — how much we care about future rewards vs. immediate ones.
- `E_π[·]` means "expectation under the stochasticity induced by policy π and the environment."

Intuition: `v_π(s)` answers *"how good is it to be in state s under policy π?"*

### Action-Value Function `q_π(s, a)`

The **action-value function** is the expected return when starting in state `s`, taking action `a` first, and *then* following policy `π`:

```
q_π(s, a) = E_π[ G_t | S_t = s, A_t = a ]
          = E_π[ Σ_{k=0}^∞ γ^k · R_{t+k+1} | S_t = s, A_t = a ]
```

Intuition: `q_π(s, a)` answers *"how good is it to take action a in state s, assuming we follow π afterwards?"*

### Relationship Between `v_π` and `q_π`

The state value is the **expectation of action values** over the policy's action distribution:

```
v_π(s) = Σ_a π(a|s) · q_π(s, a)
```

And conversely, the action value can be expanded via the one-step reward and the next state's value (the Bellman form, previewed here):

```
q_π(s, a) = E[ R_{t+1} + γ · v_π(S_{t+1}) | S_t = s, A_t = a ]
```

These identities are the foundation of the **Bellman equations** you'll derive next lecture.

---

## Why Value Functions Matter

Value functions are not just diagnostic — they are **decision-making tools**:

- They **rank policies**: a policy π is at least as good as π' if `v_π(s) ≥ v_π'(s)` for every state `s`.
- They **guide action selection**: a greedy agent picks `a = argmax_a q_π(s, a)`.
- They **enable learning without a model**: the agent can estimate values from experience instead of needing the transition probabilities `P(s'|s,a)` and reward function `R(s,a,s')` in advance.

## Worked Example: The Grid-World MDP

The slides walk through a small continuing MDP (a 3×3-ish grid) with:

- **States:** grid cells.
- **Actions:** up, down, left, right (can't leave the grid).
- **Rewards:** most actions give 0; **bumping into a wall** gives `-1`; special states `A` and `B` give `+10` and `+5` respectively, then teleport to `A'` and `B'`.
- **Discount factor:** `γ = 0.9` (needed because it's a continuing task — otherwise the sum could diverge).

After specifying a (random) policy, the value table that falls out looks something like:

| Region | Approximate `v_π(s)` | Why |
|---|---|---|
| Cells near the bottom wall | Negative (e.g., `-1.7`) | Random policy keeps bumping the wall → `-1` rewards pile up. |
| State `A` | **Highest** value | Every action jumps near the bottom wall, then random play accumulates negative bumps. |
| State `B` | Slightly above `5` | Teleports to the *middle* — safe from bumps and close to A/B. |

**Takeaway from the example:** even with the same dynamics, value numbers depend entirely on (a) the policy and (b) `γ`. Change either, and the entire table reshuffles.

## Key Takeaways

- A **policy** `π` is a mapping from states to actions — **deterministic** (`π(s) = a`) or **stochastic** (`π(a|s) = P(A=a|S=s)`). A stochastic policy is a probability distribution: non-negative and summing to 1 per state.
- The **state-value function** `v_π(s)` estimates expected return from state `s` under policy `π`.
- The **action-value function** `q_π(s, a)` estimates expected return from state `s` after taking action `a`, then following `π`.
- `v_π(s)` and `q_π(s, a)` are linked: `v_π(s) = Σ_a π(a|s) · q_π(s, a)`.
- Value functions let an agent **compare policies** and **choose actions** without needing an explicit model of the world.
- In practice, **values depend on the policy and the discount factor `γ`** — always specify both before quoting a value.
- Stochastic policies aren't just for exploration — they're required for optimal play in many adversarial and partially-observable settings.
