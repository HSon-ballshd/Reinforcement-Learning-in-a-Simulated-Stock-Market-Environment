## What Is Reinforcement Learning?

**Reinforcement Learning (RL)** is a branch of machine learning concerned with how an **agent** ought to take **actions** in an **environment** so as to maximize some notion of cumulative **reward**. The agent is not told what to do; it must discover which actions yield the most reward by *trying* them.

RL sits alongside the other two classical ML paradigms:

- **Supervised learning** — learn from labeled examples (input → correct answer). The teacher tells you the right answer.
- **Unsupervised learning** — find structure (clusters, low-dim representations) in unlabeled data. No feedback on "right/wrong."
- **Reinforcement learning** — learn from interaction, using a scalar **reward signal** that tells you how well you're doing, but *not* the correct action.

> **Analogy — training a pet:** Supervised learning is like a tutor giving you the answer key. Unsupervised learning is like organizing your bookshelf with no labels. Reinforcement learning is like training a dog with treats: you don't explain the trick, you just give a treat when it does something close to right.

## The Agent–Environment Interface

At every discrete time step `t`, the following loop happens:

```
1. Agent observes state      S_t
2. Agent takes action        A_t
3. Environment transitions   S_{t+1}
4. Environment emits reward  R_{t+1}
5. (repeat)
```

The agent's job is to learn a **policy** `π(a|s)` — a mapping from states to a distribution over actions — that maximizes the expected return.

## Key Elements of an RL System

| Element          | Symbol   | Role                                                   |     |
| ---------------- | -------- | ------------------------------------------------------ | --- |
| Policy           | `π(as)`  | The agent's behavior function                          |     |
| Reward signal    | `R_t`    | Scalar feedback from the environment                   |     |
| Value function   | `v_π(s)` | Expected return when starting in `s` and following `π` |     |
| (Optional) Model | `P, R`   | The agent's representation of environment dynamics     |     |

### Reward vs. Value — the Crucial Distinction

- **Reward** is immediate. A chocolate bar you get right now.
- **Value** is *long-term*. The expectation of all future reward from a state, assuming you keep following your current policy. A college degree has high value even though the rewards (midterms, late nights) are not obviously sweet.

> **Joke:** A reinforcement learner ordering coffee: "I'll take the small coffee now (reward = 5) — no wait, give me the loyalty card. Future me is going to need that free 10th cup (value = 50)."

## Why RL Is Hard

Unlike supervised learning, RL has several distinctive challenges:

- **No supervisor** — only a reward signal, which is often **delayed** (a chess move's quality is only revealed at checkmate).
- **Exploration vs. exploitation** — the agent must balance trying new actions (exploration) with repeating actions known to work (exploitation).
- **Sequential, non-i.i.d. data** — successive states are correlated.
- **The environment may change** as the agent learns it.

## Course Roadmap (typical of REL301m)

Based on the lecture file sequence, the course is structured around the Sutton & Barto textbook:

1. **Multi-armed bandits & exploration** (Lectures 1.1–1.3) — simplest setting: no state transitions.
2. **Markov Decision Processes (MDPs)** (1.4–1.9) — the formal framework: states, actions, rewards, the Bellman equation, optimal policies.
3. **Monte-Carlo methods** (2.1–2.4) — learn from complete episodes.
4. **Temporal-Difference learning** (2.5–2.9) — learn from incomplete episodes; introduces **Q-learning** and **SARSA**.
5. **Function approximation & policy gradient** (3.1–3.12) — scale RL to large state spaces; **actor-critic** methods, average-reward formulation.

## Why You Should Care (Applications)

- Game playing: AlphaGo, Atari, poker
- Robotics: walking, grasping, manipulation
- Operations research: inventory, routing, pricing
- Large language models: RLHF (Reinforcement Learning from Human Feedback)
- Recommendation systems, traffic control, drug discovery

> **Real-life example:** A thermostat is the simplest possible RL agent. It observes the current temperature (state), chooses to turn the heater on/off (action), and gets a reward like "comfort × −energy_used." It learns a policy over time.

## Key Takeaways

- **RL** is learning *what to do* — how to map situations to actions — to maximize a numerical reward signal.
- The **agent–environment loop** is `(S_t, A_t, R_{t+1}, S_{t+1})` repeating forever.
- The three pillars of an RL system are the **policy**, the **reward signal**, and the **value function** (plus an optional model).
- RL is distinct from supervised and unsupervised learning: the feedback is **evaluative**, not **instructive**, and is often **delayed**.
- The course progresses from bandits → MDPs → Monte-Carlo → TD learning → function approximation & policy gradients.
- The central tension in RL is **exploration vs. exploitation**.
- Mastering RL requires both the **math** (Bellman equations, convergence proofs) and the **intuition** (delayed consequences, value vs. reward).
